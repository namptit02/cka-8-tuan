# L: Mô hình mạng Kubernetes và CNI

## 4 quy tắc của mạng K8s
1. Mỗi pod có **một IP riêng**.
2. Pod nói chuyện với mọi pod khác (kể cả khác node) **không cần NAT**.
3. Agent trên node (kubelet) nói chuyện được với mọi pod trên node đó.
4. Container trong cùng pod dùng chung IP, gọi nhau qua `localhost`.

Kubernetes **không tự làm** những việc này; nó giao cho **CNI plugin**.

## CNI
- Khi kubelet tạo pod, runtime gọi plugin CNI (file thực thi trong `/opt/cni/bin`, cấu hình trong `/etc/cni/net.d/`) để tạo card mạng ảo, cấp IP, nối vào mạng chung.
- Chưa cài CNI → node **NotReady**, CoreDNS **Pending**.
- Plugin phổ biến:
| CNI | Ghi chú |
|---|---|
| Calico | phổ biến, hỗ trợ NetworkPolicy, BGP hoặc overlay |
| Cilium | dựa trên eBPF, hỗ trợ NetworkPolicy, có thể thay kube-proxy |
| Flannel | đơn giản, **không** thực thi NetworkPolicy |
- Đề có thể hỏi: "cài CNI hỗ trợ NetworkPolicy" → chọn Calico hoặc Cilium, không phải Flannel.

## Các dải IP
```bash
# Pod CIDR của cluster
kubectl cluster-info dump | grep -m1 -- --cluster-cidr
kubectl get nodes -o jsonpath='{.items[*].spec.podCIDR}'
# Service CIDR
grep service-cluster-ip-range /etc/kubernetes/manifests/kube-apiserver.yaml
# CNI đang dùng
ls /etc/cni/net.d/
```

# L: Service và kube-proxy

Pod chết là IP đổi. **Service** cho một IP và tên DNS **cố định**, cân bằng tải tới các pod khớp **selector**.

## Các loại Service
| Loại | Truy cập từ | Ghi chú |
|---|---|---|
| ClusterIP (mặc định) | trong cluster | IP ảo trong Service CIDR |
| NodePort | `<IP node>:30000-32767` | tạo thêm ClusterIP |
| LoadBalancer | IP ngoài do cloud cấp | tạo thêm NodePort; lab không cloud sẽ `<pending>` |
| ExternalName | trả về bản ghi CNAME | không có selector |
| Headless (`clusterIP: None`) | DNS trả về IP từng pod | dùng cho StatefulSet |

```yaml
apiVersion: v1
kind: Service
metadata: {name: web}
spec:
  type: NodePort
  selector: {app: web}          # chọn pod theo label
  ports:
  - port: 80                    # port của Service
    targetPort: 8080            # port của container (có thể là tên port)
    nodePort: 30080             # chỉ cho NodePort
    protocol: TCP
```

## Lệnh
```bash
kubectl expose deploy web --port=80 --target-port=8080            # ClusterIP
kubectl expose deploy web --port=80 --type=NodePort --name=web-np
kubectl expose po db --port=3306 --name=db
kubectl create svc clusterip my-svc --tcp=80:8080                  # selector app=my-svc
kubectl get svc,endpointslices
kubectl describe svc web          # dòng Endpoints: danh sách IP pod
```

## Endpoints / EndpointSlice
Controller tự cập nhật danh sách IP của pod **Ready** khớp selector. Service không có endpoint = selector sai, port sai, hoặc pod chưa Ready.

## kube-proxy
DaemonSet trên mỗi node. Theo dõi Service + EndpointSlice và viết luật iptables (mặc định) / IPVS / nftables để gói tin tới ClusterIP được chuyển tới một pod.
```bash
kubectl get ds kube-proxy -n kube-system
kubectl get cm kube-proxy -n kube-system -o yaml | grep mode
sudo iptables -t nat -L KUBE-SERVICES | head     # thấy luật cho từng Service
```

:::ex
Tạo deployment `echo` (image `hashicorp/http-echo`, args `-text=hello`, port 5678) 2 replica. Expose ClusterIP port 80 → 5678, và NodePort 30500. Test cả hai.
:::sol
```bash
kubectl create deploy echo --image=hashicorp/http-echo --replicas=2 --port=5678 -- /http-echo -text=hello
kubectl expose deploy echo --port=80 --target-port=5678
kubectl expose deploy echo --name=echo-np --type=NodePort --port=80 --target-port=5678 --dry-run=client -o yaml > np.yaml
# thêm nodePort: 30500 dưới ports[0]
kubectl apply -f np.yaml
kubectl run t --image=busybox --rm -it --restart=Never -- wget -qO- echo
curl http://<node-ip>:30500
```
:::end

:::ex

:::sol

# L: DNS và CoreDNS

## Tên DNS trong cluster
| Đối tượng | Tên |
|---|---|
| Service | `<svc>.<namespace>.svc.cluster.local` |
| Pod (theo IP) | `10-244-1-5.<namespace>.pod.cluster.local` |
| Pod trong StatefulSet | `<pod>.<headless-svc>.<namespace>.svc.cluster.local` |

Trong cùng namespace chỉ cần gọi `<svc>`; khác namespace dùng `<svc>.<namespace>`. Do `/etc/resolv.conf` của pod có dòng `search <ns>.svc.cluster.local svc.cluster.local cluster.local`.

## CoreDNS
- Deployment `coredns` trong `kube-system`, Service tên **kube-dns** (IP thường là `10.96.0.10`).
- Cấu hình: ConfigMap `coredns`, key `Corefile`.
- kubelet ghi IP DNS vào pod theo `clusterDNS` trong `/var/lib/kubelet/config.yaml`.
```bash
kubectl get deploy,svc -n kube-system -l k8s-app=kube-dns
kubectl get cm coredns -n kube-system -o yaml
kubectl logs -n kube-system -l k8s-app=kube-dns
```
Corefile mẫu:
```text
.:53 {
    errors
    health
    kubernetes cluster.local in-addr.arpa ip6.arpa {
       pods insecure
       fallthrough in-addr.arpa ip6.arpa
    }
    forward . /etc/resolv.conf
    cache 30
    loop
    reload
}
```
Sau khi sửa ConfigMap: `kubectl rollout restart deploy coredns -n kube-system` (hoặc đợi plugin `reload`).

## dnsPolicy
`ClusterFirst` (mặc định), `Default` (dùng DNS của node), `None` (tự khai báo `dnsConfig`), `ClusterFirstWithHostNet` (pod hostNetwork).

:::ex
Từ một pod trong namespace `default`, phân giải service `kube-dns` ở `kube-system` theo 3 cách viết tên: ngắn có namespace, đầy đủ FQDN, và xem file resolv.conf của pod.
:::sol
```bash
kubectl run d --image=busybox:1.36 --rm -it --restart=Never -- sh
nslookup kube-dns.kube-system
nslookup kube-dns.kube-system.svc.cluster.local
cat /etc/resolv.conf
```
:::end

:::ex
Sự cố DNS: scale CoreDNS về 0 replica, thử nslookup, rồi khôi phục. Ghi lại thông báo lỗi.
:::sol
```bash
kubectl scale deploy coredns -n kube-system --replicas=0
kubectl run d --image=busybox:1.36 --rm -it --restart=Never -- nslookup kubernetes   # timeout / no servers could be reached
kubectl scale deploy coredns -n kube-system --replicas=2
```
:::end

:::ex
Thêm vào CoreDNS để mọi truy vấn `*.corp.local` được chuyển tới DNS `10.0.0.53`.
:::sol
Sửa ConfigMap `coredns`, thêm khối mới cạnh khối `.:53`:

# L: NetworkPolicy

Mặc định **mọi pod nói chuyện được với mọi pod**. NetworkPolicy là tường lửa ở mức pod, cần CNI hỗ trợ (Calico, Cilium).

## Nguyên tắc
- Pod **không** bị policy nào chọn → cho phép tất cả.
- Pod bị ít nhất 1 policy chọn cho chiều Ingress → chỉ cho những gì policy **cho phép** (whitelist). Tương tự với Egress.
- Nhiều policy cộng dồn (hợp các luật cho phép).

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: api-policy, namespace: prod}
spec:
  podSelector:                 # policy áp cho pod nào ({} = mọi pod trong ns)
    matchLabels: {app: api}
  policyTypes: [Ingress, Egress]
  ingress:
  - from:
    - podSelector: {matchLabels: {app: web}}            # pod web cùng namespace
    - namespaceSelector: {matchLabels: {kubernetes.io/metadata.name: monitoring}}  # mọi pod ns monitoring
    - ipBlock: {cidr: 10.0.0.0/24}
    ports:
    - {protocol: TCP, port: 8080}
  egress:
  - to:
    - podSelector: {matchLabels: {app: db}}
    ports: [{protocol: TCP, port: 5432}]
  - ports:                     # cho phép DNS, nếu không pod không phân giải được tên!
    - {protocol: UDP, port: 53}
    - {protocol: TCP, port: 53}
```

## AND vs OR – bẫy kinh điển
```yaml
# OR: pod app=web (cùng ns) HOẶC mọi pod trong ns có label team=a
- from:
  - podSelector: {matchLabels: {app: web}}
  - namespaceSelector: {matchLabels: {team: a}}

# AND: pod app=web NẰM TRONG ns có label team=a (cùng 1 gạch đầu dòng)
- from:
  - podSelector: {matchLabels: {app: web}}
    namespaceSelector: {matchLabels: {team: a}}
```

## Mẫu hay dùng
```yaml
# Chặn mọi ingress trong namespace
spec: {podSelector: {}, policyTypes: [Ingress]}
# Chặn mọi egress
spec: {podSelector: {}, policyTypes: [Egress]}
# Cho phép mọi ingress
spec: {podSelector: {}, ingress: [{}], policyTypes: [Ingress]}
```
Mỗi namespace tự có label `kubernetes.io/metadata.name=<tên>` → dùng để chọn namespace theo tên.

:::ex
Namespace `np`: tạo pod `web` (nginx, label app=web), `client` (busybox sleep, label role=client), `other` (busybox sleep). Viết policy chỉ cho pod role=client gọi web port 80. Kiểm tra từ client (được) và other (bị chặn).
:::sol
```bash
kubectl create ns np
kubectl run web --image=nginx -l app=web -n np
kubectl run client --image=busybox -l role=client -n np -- sleep 3600
kubectl run other --image=busybox -n np -- sleep 3600
kubectl expose po web --port=80 -n np
cat <<EOF | kubectl apply -f -
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: web-allow-client, namespace: np}
spec:
  podSelector: {matchLabels: {app: web}}
  policyTypes: [Ingress]
  ingress:
  - from: [{podSelector: {matchLabels: {role: client}}}]
    ports: [{protocol: TCP, port: 80}]
EOF
kubectl exec -n np client -- wget -qO- -T 3 web    # OK
kubectl exec -n np other -- wget -qO- -T 3 web     # timeout
```
:::end

:::ex
Thêm policy chặn mọi egress của pod `client` ngoại trừ tới `web:80` và DNS. Kiểm tra `wget google.com` bị chặn.
:::sol
```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: client-egress, namespace: np}
spec:
  podSelector: {matchLabels: {role: client}}
  policyTypes: [Egress]
  egress:
  - to: [{podSelector: {matchLabels: {app: web}}}]
    ports: [{protocol: TCP, port: 80}]
  - ports: [{protocol: UDP, port: 53}, {protocol: TCP, port: 53}]
```
```bash
kubectl exec -n np client -- wget -qO- -T 3 web           # OK
kubectl exec -n np client -- wget -qO- -T 3 google.com    # timeout
```
:::end

:::ex
Cho phép pod `app=db` ở namespace `data` chỉ nhận kết nối port 5432 từ pod `app=api` thuộc namespace `backend`.
:::sol
```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: db-from-api, namespace: data}
spec:
  podSelector: {matchLabels: {app: db}}
  policyTypes: [Ingress]
  ingress:
  - from:
    - namespaceSelector: {matchLabels: {kubernetes.io/metadata.name: backend}}
      podSelector: {matchLabels: {app: api}}       # cùng 1 phần tử = AND
    ports: [{protocol: TCP, port: 5432}]
```
:::end

# L: Ingress và Gateway API

## Ingress
Định tuyến HTTP/HTTPS từ ngoài vào Service theo **host** và **path**. Cần **Ingress controller** (ingress-nginx, Traefik…) chạy trong cluster; Ingress chỉ là luật.
```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata: {name: shop}
spec:
  ingressClassName: nginx
  tls:
  - hosts: [shop.local]
    secretName: shop-tls
  rules:
  - host: shop.local
    http:
      paths:
      - path: /api
        pathType: Prefix          # Prefix | Exact | ImplementationSpecific
        backend: {service: {name: api, port: {number: 8080}}}
      - path: /
        pathType: Prefix
        backend: {service: {name: web, port: {number: 80}}}
```
```bash
kubectl create ingress shop --class=nginx --rule="shop.local/api*=api:8080" --rule="shop.local/*=web:80"
kubectl get ingressclass
kubectl describe ingress shop
curl -H "Host: shop.local" http://<ip-ingress-controller>:<nodeport>/api
```

## Gateway API – thế hệ sau của Ingress (có trong đề hiện tại)
Tách vai trò rõ ràng:
| Tài nguyên | Ai quản lý | Vai trò |
|---|---|---|
| **GatewayClass** | nhà cung cấp hạ tầng | loại controller (như IngressClass) |
| **Gateway** | đội vận hành cluster | điểm vào: listener, port, protocol, hostname, TLS |
| **HTTPRoute** | đội ứng dụng | luật định tuyến tới Service, gắn vào Gateway qua `parentRefs` |

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata: {name: web-gw}
spec:
  gatewayClassName: nginx
  listeners:
  - name: http
    protocol: HTTP
    port: 80
    hostname: shop.local
  - name: https
    protocol: HTTPS
    port: 443
    hostname: shop.local
    tls:
      mode: Terminate
      certificateRefs: [{kind: Secret, name: shop-tls}]
---
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata: {name: shop-route}
spec:
  parentRefs: [{name: web-gw}]
  hostnames: [shop.local]
  rules:
  - matches: [{path: {type: PathPrefix, value: /api}}]
    backendRefs: [{name: api, port: 8080}]
  - matches: [{path: {type: PathPrefix, value: /}}]
    backendRefs:                       # chia tải theo trọng số (canary)
    - {name: web-v1, port: 80, weight: 90}
    - {name: web-v2, port: 80, weight: 10}
```
Gateway API còn hỗ trợ match theo header, sửa header, redirect (`filters`). Dạng đề hay gặp: **chuyển một Ingress có sẵn sang Gateway + HTTPRoute** giữ nguyên host, path, TLS.
```bash
kubectl get gatewayclass,gateway,httproute
kubectl describe httproute shop-route      # xem điều kiện Accepted / ResolvedRefs
```
Tài liệu được mở trong phòng thi: gateway-api.sigs.k8s.io.

:::ex
Cài ingress-nginx (bản baremetal, NodePort). Tạo 2 deployment `app1`, `app2` (http-echo trả "one"/"two") kèm Service, và Ingress: `demo.local/one` → app1, `demo.local/two` → app2. Test bằng curl với header Host.
:::sol
```bash
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/main/deploy/static/provider/baremetal/deploy.yaml
kubectl create deploy app1 --image=hashicorp/http-echo -- /http-echo -text=one
kubectl create deploy app2 --image=hashicorp/http-echo -- /http-echo -text=two
kubectl expose deploy app1 --port=80 --target-port=5678
kubectl expose deploy app2 --port=80 --target-port=5678
kubectl create ingress demo --class=nginx --rule="demo.local/one=app1:80" --rule="demo.local/two=app2:80"
kubectl get svc -n ingress-nginx      # lấy NodePort của http
curl -H "Host: demo.local" http://<node-ip>:<nodeport>/one
```
(Với path Exact như trên, `/one` khớp; muốn mọi đường dẫn con dùng `/one*` → Prefix.)
:::end

:::ex
Chuyển Ingress `demo` ở trên sang Gateway API: có sẵn GatewayClass `nginx`. Tạo Gateway `demo-gw` listener HTTP port 80 host demo.local, và HTTPRoute tương ứng.
:::sol
```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata: {name: demo-gw}
spec:
  gatewayClassName: nginx
  listeners:
  - {name: http, protocol: HTTP, port: 80, hostname: demo.local}
---
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata: {name: demo-route}
spec:
  parentRefs: [{name: demo-gw}]
  hostnames: [demo.local]
  rules:
  - matches: [{path: {type: PathPrefix, value: /one}}]
    backendRefs: [{name: app1, port: 80}]
  - matches: [{path: {type: PathPrefix, value: /two}}]
    backendRefs: [{name: app2, port: 80}]
```
```bash
kubectl get gateway demo-gw ; kubectl describe httproute demo-route
```
(Để chạy thật cần cài một Gateway controller, ví dụ NGINX Gateway Fabric hoặc Envoy Gateway, cùng CRD Gateway API.)
:::end

:::ex
Thêm vào `demo-route` luật: request có header `x-env: canary` tới `/one` thì đi tới `app2`.
:::sol
```yaml
  rules:
  - matches:
    - path: {type: PathPrefix, value: /one}
      headers: [{name: x-env, value: canary}]
    backendRefs: [{name: app2, port: 80}]
  # ... các rule cũ giữ nguyên
```
Rule có điều kiện cụ thể hơn (path + header) được ưu tiên hơn rule chỉ có path.
:::end
