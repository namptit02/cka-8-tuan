# L: Kiến trúc Kubernetes

## Control plane (bộ não)
| Thành phần | Nhiệm vụ | Chạy dưới dạng (kubeadm) |
|---|---|---|
| **kube-apiserver** | Cửa ngõ duy nhất. Mọi thành phần và kubectl đều nói chuyện qua nó (port 6443). Xác thực, phân quyền, lưu vào etcd. | static pod |
| **etcd** | Database key-value lưu **toàn bộ trạng thái** cluster. Mất etcd = mất cluster. | static pod |
| **kube-scheduler** | Chọn node cho pod mới (pod chưa có `nodeName`). | static pod |
| **kube-controller-manager** | Chạy các vòng lặp điều khiển: Deployment → ReplicaSet → Pod, Node, Endpoint, ServiceAccount… | static pod |
| cloud-controller-manager | Tích hợp cloud (LoadBalancer, volume). Thường không có trong lab. | |

## Worker node (tay chân)
| Thành phần | Nhiệm vụ |
|---|---|
| **kubelet** | Agent trên mỗi node, là **service systemd**. Nhận pod được gán cho node, gọi runtime qua CRI để chạy, báo trạng thái về apiserver. Cũng chạy static pod từ `/etc/kubernetes/manifests`. |
| **kube-proxy** | DaemonSet. Lập trình iptables/IPVS/nftables để Service hoạt động. |
| **container runtime** | containerd/CRI-O, chạy container thật sự. |
| **CNI plugin** | Cấp IP cho pod, nối mạng giữa các node (Calico, Cilium, Flannel). |
| **CoreDNS** | Deployment trong `kube-system`, phân giải tên Service. |

## Điều gì xảy ra khi bạn `kubectl create deployment`
1. kubectl gửi yêu cầu HTTPS tới **apiserver**.
2. apiserver xác thực (bạn là ai), phân quyền RBAC (được làm không), chạy admission controllers, rồi **lưu vào etcd**.
3. **Deployment controller** (trong controller-manager) thấy Deployment mới → tạo **ReplicaSet**.
4. **ReplicaSet controller** tạo đủ số **Pod** (chưa có node).
5. **Scheduler** thấy pod chưa có node → lọc node phù hợp (tài nguyên, taint, affinity) → chấm điểm → ghi `nodeName`.
6. **kubelet** trên node đó thấy pod của mình → gọi containerd tạo container, CNI cấp IP.
7. kubelet báo trạng thái `Running` về apiserver.

Mọi thành phần **chỉ nói chuyện với apiserver**, không nói chuyện trực tiếp với nhau. Các controller hoạt động theo kiểu **reconcile**: liên tục so trạng thái mong muốn (spec) với thực tế (status) và sửa cho khớp.

## Static pod
- kubelet đọc thư mục `staticPodPath` (mặc định `/etc/kubernetes/manifests`) và tự chạy pod trong đó, **không cần apiserver**. Đó là cách control plane khởi động được.
- Tên pod có hậu tố tên node: `kube-apiserver-controlplane`.
- Xoá bằng kubectl thì nó tự sống lại. Muốn xoá thật: xoá/move file YAML khỏi thư mục.
- Sửa file → kubelet tự tạo lại pod.

:::ex
Liệt kê các pod control plane, xác định pod nào là static pod và đường dẫn staticPodPath của kubelet.
:::sol
```bash
kubectl get po -n kube-system -o wide
ls /etc/kubernetes/manifests
grep staticPodPath /var/lib/kubelet/config.yaml
# Static pod có ownerReferences kind: Node
kubectl get po kube-apiserver-controlplane -n kube-system -o jsonpath='{.metadata.ownerReferences[0].kind}'
```
:::end

:::ex
Tạo static pod tên `static-web` (image nginx) trên **node01**.
:::sol
```bash
kubectl run static-web --image=nginx --dry-run=client -o yaml > static-web.yaml
scp static-web.yaml node01:/tmp/
ssh node01
sudo cp /tmp/static-web.yaml /etc/kubernetes/manifests/
exit
kubectl get po        # static-web-node01
```
:::end

:::ex
Nếu kube-scheduler chết, điều gì xảy ra với (a) pod đang chạy, (b) pod mới tạo? Nếu etcd chết thì sao?
:::sol
(a) Pod đang chạy vẫn chạy bình thường (kubelet vẫn giữ). (b) Pod mới ở trạng thái **Pending** mãi, không có event "Scheduled".
etcd chết → apiserver không đọc/ghi được → kubectl lỗi, không thay đổi được gì; pod đang chạy vẫn chạy nhưng không ai quản lý.
:::end

# L: kubectl, kubeconfig và namespace

## kubeconfig
File `~/.kube/config` (hoặc biến `KUBECONFIG`) gồm 3 phần:
- **clusters**: địa chỉ apiserver + CA.
- **users**: thông tin xác thực (client cert, token).
- **contexts**: cặp cluster + user + namespace mặc định.

```bash
kubectl config get-contexts
kubectl config current-context
kubectl config use-context k8s-cluster2        # ĐỀ THI: chạy lệnh này đầu mỗi câu
kubectl config set-context --current --namespace=dev   # đổi namespace mặc định
kubectl config view --minify                   # chỉ context hiện tại
kubectl --kubeconfig /path/other.conf get nodes
```

## Namespace
Chia cluster thành các vùng logic. Mặc định có: `default`, `kube-system`, `kube-public`, `kube-node-lease`.
```bash
kubectl get ns
kubectl create ns dev
kubectl get po -n dev
kubectl get po -A                   # mọi namespace
kubectl api-resources --namespaced=false   # tài nguyên không thuộc namespace: node, pv, clusterrole, sc...
```

## Imperative vs declarative
- **Imperative** (`kubectl run/create/expose/scale/set`): nhanh, dùng nhiều trong thi.
- **Declarative** (`kubectl apply -f`): file YAML là nguồn sự thật.
- Kết hợp: sinh YAML bằng imperative rồi sửa:
```bash
kubectl create deploy web --image=nginx --dry-run=client -o yaml > web.yaml
vim web.yaml
kubectl apply -f web.yaml
```
- Sửa trực tiếp: `kubectl edit deploy web`. Với trường không sửa được của pod, kubectl lưu bản sửa vào `/tmp/kubectl-edit-xxx.yaml` → dùng `kubectl replace --force -f /tmp/kubectl-edit-xxx.yaml`.

## Tra cứu
```bash
kubectl explain pod.spec.containers.resources
kubectl explain deploy.spec --recursive | less
kubectl get po web -o yaml
kubectl describe po web
kubectl get all -n dev
```

:::ex
Tạo namespace `w2`, đặt nó làm namespace mặc định cho context hiện tại, tạo pod `p1` (nginx) mà không ghi `-n`, kiểm tra pod nằm ở `w2`, rồi đặt lại về `default`.
:::sol
```bash
kubectl create ns w2
kubectl config set-context --current --namespace=w2
kubectl run p1 --image=nginx
kubectl get po -n w2
kubectl config set-context --current --namespace=default
```
:::end

:::ex
Ghi tên mọi context vào `/root/contexts.txt` (chỉ tên, mỗi dòng 1 tên) và context hiện tại vào `/root/current.txt`.
:::sol
```bash
kubectl config get-contexts -o name > /root/contexts.txt
kubectl config current-context > /root/current.txt
```
:::end

:::ex
Liệt kê tất cả loại tài nguyên **không** thuộc namespace, ghi tên vào `/root/cluster-scoped.txt`.
:::sol
```bash
kubectl api-resources --namespaced=false -o name > /root/cluster-scoped.txt
```
:::end

# L: Pod, label và selector

## Pod
Đơn vị nhỏ nhất K8s chạy. Một pod có 1 hoặc nhiều container, **chung IP, chung volume**, luôn nằm trên cùng 1 node.
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: web
  labels: {app: web, tier: frontend}
spec:
  containers:
  - name: nginx
    image: nginx:1.27
    ports:
    - containerPort: 80
    env:
    - name: MODE
      value: prod
  restartPolicy: Always     # Always (mặc định) | OnFailure | Never
```

## Trạng thái pod
| Phase/Status | Ý nghĩa |
|---|---|
| Pending | chưa được schedule hoặc đang kéo image |
| ContainerCreating | đã có node, đang tạo container |
| Running | ít nhất 1 container đang chạy |
| Succeeded / Completed | mọi container thoát với mã 0 |
| Failed / Error | container thoát với mã khác 0 |
| CrashLoopBackOff | container chết đi chết lại, kubelet chờ lâu dần rồi mới thử lại |
| ImagePullBackOff / ErrImagePull | sai tên image/tag, không có quyền registry |

## Lệnh với Pod
```bash
kubectl run web --image=nginx --port=80 --labels=app=web,tier=fe
kubectl run bb --image=busybox --restart=Never -- sleep 3600     # args
kubectl run bb --image=busybox --command -- sh -c "echo hi"      # command
kubectl run tmp --image=busybox --rm -it --restart=Never -- sh   # pod tạm để debug
kubectl get po -o wide            # xem IP và node
kubectl logs web ; kubectl logs web -c sidecar ; kubectl logs web -f
kubectl exec -it web -- bash
kubectl exec web -- cat /etc/resolv.conf
kubectl delete po web --force --grace-period=0     # xoá ngay
```

## Label, selector, annotation
- **Label**: cặp key=value để nhóm và chọn đối tượng. Service, Deployment, NetworkPolicy đều chọn pod bằng label.
- **Annotation**: metadata không dùng để chọn (ghi chú, cấu hình cho tool).
```bash
kubectl label po web env=prod
kubectl label po web env=dev --overwrite
kubectl label po web env-            # xoá label
kubectl get po -l app=web
kubectl get po -l 'env in (prod,dev)'
kubectl get po -l app=web,env!=prod
kubectl get po --show-labels
kubectl annotate po web owner=team-a
```

:::ex
Tạo pod `multi` có 2 container: `web` (nginx) và `helper` (busybox chạy `sleep 3600`). Từ container `helper`, gọi `wget -qO- localhost` để thấy trang nginx.
:::sol
```yaml
apiVersion: v1
kind: Pod
metadata: {name: multi}
spec:
  containers:
  - name: web
    image: nginx
  - name: helper
    image: busybox
    command: ["sleep", "3600"]
```
```bash
kubectl apply -f multi.yaml
kubectl exec multi -c helper -- wget -qO- localhost
```
:::end

:::ex
Tạo 3 pod `a`, `b`, `c` (nginx) với label `env=prod`, `env=dev`, `env=prod`. Ghi tên các pod prod vào `/root/prod.txt`. Sau đó đổi label của `c` thành `env=dev`.
:::sol
```bash
kubectl run a --image=nginx -l env=prod
kubectl run b --image=nginx -l env=dev
kubectl run c --image=nginx -l env=prod
kubectl get po -l env=prod -o name > /root/prod.txt    # dạng pod/a
# hoặc chỉ tên: kubectl get po -l env=prod --no-headers | awk '{print $1}'
kubectl label po c env=dev --overwrite
```
:::end

:::ex
Tạo pod `bad` với image `nginx:khongcotag`. Quan sát trạng thái, tìm thông báo lỗi trong events rồi sửa image thành `nginx:1.27`.
:::sol
```bash
kubectl run bad --image=nginx:khongcotag
kubectl get po bad          # ErrImagePull -> ImagePullBackOff
kubectl describe po bad | tail     # "manifest unknown" / not found
kubectl set image po bad bad=nginx:1.27   # image là trường duy nhất sửa được của pod đang chạy
```
:::end

# L: Deployment, ReplicaSet, rolling update

## Quan hệ
**Deployment** → quản lý **ReplicaSet** → quản lý **Pod**. Mỗi lần đổi pod template (image, env…) Deployment tạo ReplicaSet mới và chuyển dần pod sang đó.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata: {name: web}
spec:
  replicas: 3
  selector:
    matchLabels: {app: web}     # PHẢI khớp label của template
  strategy:
    type: RollingUpdate          # hoặc Recreate (xoá hết rồi tạo mới, có downtime)
    rollingUpdate:
      maxSurge: 1                # tối đa thêm 1 pod so với replicas khi update
      maxUnavailable: 0          # không cho pod nào thiếu
  template:
    metadata:
      labels: {app: web}
    spec:
      containers:
      - name: nginx
        image: nginx:1.27
```

## Lệnh
```bash
kubectl create deploy web --image=nginx:1.27 --replicas=3
kubectl scale deploy web --replicas=5
kubectl set image deploy/web nginx=nginx:1.28       # nginx = tên container
kubectl rollout status deploy/web
kubectl rollout history deploy/web
kubectl rollout history deploy/web --revision=2
kubectl annotate deploy web kubernetes.io/change-cause="update to 1.28"   # ghi chú cho history
kubectl rollout undo deploy/web                     # về bản trước
kubectl rollout undo deploy/web --to-revision=1
kubectl rollout pause deploy/web ; kubectl rollout resume deploy/web
kubectl rollout restart deploy/web                  # tạo lại toàn bộ pod
kubectl get rs                                      # thấy ReplicaSet cũ có 0 pod
```

:::ex
Tạo deployment `w2-web` (nginx:1.27, 4 replica) với chiến lược `maxSurge: 2`, `maxUnavailable: 1`. Update lên `nginx:1.28` và ghi change-cause. Kiểm tra history có 2 revision.
:::sol
```bash
kubectl create deploy w2-web --image=nginx:1.27 --replicas=4 --dry-run=client -o yaml > w2.yaml
# thêm dưới spec:
#   strategy:
#     type: RollingUpdate
#     rollingUpdate: {maxSurge: 2, maxUnavailable: 1}
kubectl apply -f w2.yaml
kubectl set image deploy/w2-web nginx=nginx:1.28
kubectl annotate deploy w2-web kubernetes.io/change-cause="nginx 1.28"
kubectl rollout history deploy/w2-web
```
:::end

:::ex
Update `w2-web` lên image lỗi `nginx:9.9.9`. Quan sát: bao nhiêu pod cũ vẫn chạy? Rollback lại.
:::sol
```bash
kubectl set image deploy/w2-web nginx=nginx:9.9.9
kubectl get po        # vài pod mới ImagePullBackOff, pod cũ vẫn chạy (ít nhất replicas - maxUnavailable = 3)
kubectl rollout status deploy/w2-web    # treo, Ctrl+C
kubectl rollout undo deploy/w2-web
```
Đây là lý do rolling update an toàn: lỗi không làm sập toàn bộ ứng dụng.
:::end

:::ex
Chuyển `w2-web` sang chiến lược `Recreate`.
:::sol
```bash
kubectl patch deploy w2-web -p '{"spec":{"strategy":{"type":"Recreate","rollingUpdate":null}}}'
# hoặc kubectl edit: đổi type: Recreate và XOÁ khối rollingUpdate (nếu không sẽ bị báo lỗi)
```
:::end

# L: Định dạng đầu ra: jsonpath, custom-columns, sort

Đề hay có câu "ghi X vào file theo định dạng Y".

```bash
kubectl get po web -o yaml           # xem cấu trúc để viết jsonpath
kubectl get po -o name               # pod/a pod/b
kubectl get po -o wide
```

## jsonpath
```bash
kubectl get po web -o jsonpath='{.spec.containers[0].image}'
kubectl get po -o jsonpath='{.items[*].metadata.name}'           # tên mọi pod, cách nhau dấu cách
kubectl get po -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.podIP}{"\n"}{end}'
kubectl get nodes -o jsonpath='{.items[*].status.addresses[?(@.type=="InternalIP")].address}'
kubectl get secret s -o jsonpath='{.data.password}' | base64 -d
kubectl config view -o jsonpath='{.users[*].name}'
```
- `.items[*]` khi lấy danh sách, `[0]` phần tử đầu, `[?(@.x=="y")]` lọc.
- `range ... end` để in nhiều dòng.

## custom-columns
```bash
kubectl get po -o custom-columns=NAME:.metadata.name,IMAGE:.spec.containers[0].image,NODE:.spec.nodeName
kubectl get nodes -o custom-columns=NODE:.metadata.name,CPU:.status.capacity.cpu
```

## sort-by
```bash
kubectl get po --sort-by=.metadata.creationTimestamp
kubectl get pv --sort-by=.spec.capacity.storage
kubectl get po -A --sort-by=.status.containerStatuses[0].restartCount
```

:::ex
Ghi InternalIP của mọi node vào `/root/node-ips.txt`, cách nhau dấu cách.
:::sol
```bash
kubectl get nodes -o jsonpath='{.items[*].status.addresses[?(@.type=="InternalIP")].address}' > /root/node-ips.txt
```
:::end

:::ex
In bảng 2 cột `POD` và `NODE` cho mọi pod ở `kube-system`, sắp theo tên node.
:::sol
```bash
kubectl get po -n kube-system -o custom-columns=POD:.metadata.name,NODE:.spec.nodeName --sort-by=.spec.nodeName
```
:::end

:::ex
In mỗi dòng: tên node và số CPU (capacity), dùng jsonpath range.
:::sol
```bash
kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name}{" "}{.status.capacity.cpu}{"\n"}{end}'
```
:::end

:::ex
Liệt kê PersistentVolume sắp theo dung lượng, ghi vào `/root/pv-sorted.txt`.
:::sol
```bash
kubectl get pv --sort-by=.spec.capacity.storage > /root/pv-sorted.txt
```
:::end
