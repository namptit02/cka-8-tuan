# L: Phương pháp troubleshooting và lỗi ứng dụng

## Quy trình 4 bước
1. **Quan sát**: `kubectl get` – cái gì không ổn (STATUS, READY, RESTARTS)?
2. **Đọc events**: `kubectl describe` – phần Events cuối cùng thường nói thẳng lý do.
3. **Đọc log**: `kubectl logs`, `--previous`, log node (`journalctl`, `crictl`).
4. **Sửa và xác minh**: sửa từng chỗ, kiểm tra lại.

```bash
kubectl get po -A | grep -v -E 'Running|Completed'
kubectl get events -A --sort-by=.lastTimestamp | tail -20
kubectl get events -n prod --field-selector type=Warning
kubectl describe po <pod>
kubectl logs <pod> [-c container] [--previous] [--tail=50]
kubectl get po <pod> -o yaml | less
```

## Bảng tra lỗi pod
| Trạng thái | Nguyên nhân hay gặp | Xem ở đâu |
|---|---|---|
| Pending | thiếu CPU/RAM, taint, nodeSelector/affinity không khớp, PVC chưa bind, scheduler chết | `describe` → Events |
| ContainerCreating lâu | CNI lỗi, volume/secret/configmap không tồn tại | `describe` → Events |
| ImagePullBackOff | sai tên/tag, registry riêng thiếu `imagePullSecrets` | `describe` |
| CrashLoopBackOff | lệnh sai, app lỗi cấu hình, thiếu biến, liveness probe fail | `logs --previous`, `describe` (Exit Code) |
| OOMKilled (137) | vượt limit memory | `describe` → Last State |
| CreateContainerConfigError | tham chiếu key ConfigMap/Secret không tồn tại | `describe` |
| Running nhưng 0/1 Ready | readiness probe fail | `describe` |
| Terminating mãi | finalizer, node chết | `kubectl delete --force --grace-period=0` |

## Exit code
`0` thành công · `1` lỗi chung của app · `126` không thực thi được · `127` không tìm thấy lệnh · `137` SIGKILL/OOM · `139` segfault · `143` SIGTERM.

:::ex
Tạo pod `ts1` với image `busybox` và lệnh `shh -c "sleep 3600"` (gõ sai). Chẩn đoán từ trạng thái, exit code, và sửa.
:::sol
```bash
kubectl run ts1 --image=busybox --command -- shh -c "sleep 3600"
kubectl get po ts1                 # RunContainerError / CrashLoopBackOff
kubectl describe po ts1 | grep -iE "exit code|reason|message"   # executable file not found (127)
kubectl delete po ts1
kubectl run ts1 --image=busybox --command -- sh -c "sleep 3600"
```
:::end

:::ex
Tạo pod tham chiếu `configMapKeyRef` tới ConfigMap `khong-co`. Trạng thái là gì? Sửa bằng cách tạo ConfigMap.
:::sol
```bash
kubectl get po        # CreateContainerConfigError
kubectl describe po <pod> | tail -5     # configmap "khong-co" not found
kubectl create cm khong-co --from-literal=<key>=value
kubectl get po -w     # tự chuyển Running
```
:::end

:::ex
Liệt kê 10 sự kiện Warning gần nhất của toàn cluster và ghi vào `/root/warnings.txt`.
:::sol
```bash
kubectl get events -A --field-selector type=Warning --sort-by=.lastTimestamp | tail -10 > /root/warnings.txt
```
:::end

# L: Sự cố control plane

Khi control plane hỏng, `kubectl` thường không dùng được. Làm việc **trên control plane node** bằng file và crictl.

## Kiểm tra
```bash
kubectl get po -n kube-system                # nếu còn dùng được
sudo crictl ps -a | grep -E 'apiserver|etcd|scheduler|controller'
sudo crictl logs <id>
ls /var/log/pods/ ; sudo tail /var/log/pods/kube-system_kube-apiserver-*/kube-apiserver/*.log
sudo journalctl -u kubelet | grep -i -E 'apiserver|error' | tail
```

## Lỗi hay bị "cài sẵn" trong đề
| Thành phần | Triệu chứng | Lỗi trong manifest |
|---|---|---|
| kube-apiserver | `connection refused :6443`, kubectl chết | sai đường dẫn cert/key, sai `--etcd-servers` (port 2379), cờ không tồn tại, sai YAML |
| etcd | apiserver liên tục restart | sai `--data-dir` / hostPath, sai cert |
| kube-scheduler | pod mới Pending, không có event Scheduled | sai `--kubeconfig`, sai image, sai cờ |
| kube-controller-manager | Deployment không tạo pod, scale không có tác dụng | sai `--kubeconfig`, sai đường dẫn cert CA, sai cờ |

## Cách sửa
```bash
sudo cp /etc/kubernetes/manifests/kube-apiserver.yaml /root/apiserver.bak    # backup trước
sudo vim /etc/kubernetes/manifests/kube-apiserver.yaml
# lưu → kubelet tự phát hiện và tạo lại container (có thể mất 30–90 giây)
watch sudo crictl ps
```
Mẹo: so sánh đường dẫn trong manifest với file thật bằng `ls /etc/kubernetes/pki/`. Nếu YAML sai cú pháp, kubelet log sẽ báo lỗi parse và **không có container nào** được tạo.

:::ex
(Lab tự dựng) Backup manifest, sửa `--etcd-servers=https://127.0.0.1:2379` thành `:2380` trong kube-apiserver.yaml. Chẩn đoán và sửa.
:::sol
```bash

sudo crictl ps -a | grep apiserver          # Exited liên tục
sudo crictl logs $(sudo crictl ps -a --name kube-apiserver -q | head -1) 2>&1 | tail
# thấy lỗi kết nối etcd ở 2380
sudo cp /root/apiserver.bak /etc/kubernetes/manifests/kube-apiserver.yaml   # hoặc sửa lại 2379
```
:::end

:::ex
(Lab tự dựng) Đổi `--kubeconfig=/etc/kubernetes/scheduler.conf` thành `scheduler.con` trong kube-scheduler.yaml. Tạo một pod mới và chẩn đoán.
:::sol
```bash

kubectl get po sched-test               # Pending, không event
kubectl get po -n kube-system | grep scheduler     # CrashLoopBackOff
```

:::end

# L: Sự cố worker node

## Node NotReady – checklist
```bash
kubectl get nodes
kubectl describe node node01 | grep -A10 Conditions    # Ready=Unknown: kubelet mất liên lạc
ssh node01 ; sudo -i
systemctl status kubelet
journalctl -u kubelet --no-pager | tail -30
systemctl status containerd
```
| Lỗi trong log kubelet | Nguyên nhân | Sửa |
|---|---|---|
| service inactive/dead | kubelet bị stop/disable | `systemctl enable --now kubelet` |
| failed to load kubelet config file | sai đường dẫn/ YAML hỏng `/var/lib/kubelet/config.yaml` | sửa file |
| unable to load client CA file | `clientCAFile` sai đường dẫn | sửa thành `/etc/kubernetes/pki/ca.crt` |
| connect: connection refused (6443) / sai port | `server:` trong `/etc/kubernetes/kubelet.conf` sai | sửa địa chỉ apiserver |
| container runtime is down / not ready | containerd chết, sai socket | `systemctl restart containerd` |
| network plugin not ready / cni config uninitialized | CNI chưa chạy / thiếu file `/etc/cni/net.d` | kiểm tra pod CNI trên node |
| executable file not found (binary) | sai `ExecStart` trong drop-in | `systemctl cat kubelet`, sửa, daemon-reload |

Sau khi sửa: `systemctl daemon-reload && systemctl restart kubelet`, rồi `exit` về máy chính và `kubectl get nodes`.

## Áp lực tài nguyên
Condition `MemoryPressure`, `DiskPressure`, `PIDPressure` = True → kubelet đuổi (evict) pod và node bị taint tương ứng.
```bash
df -h ; free -m
sudo crictl rmi --prune          # dọn image không dùng khi đầy ổ
```

:::ex
(Lab) Trên node01, sửa `/var/lib/kubelet/config.yaml`: đổi `clientCAFile` thành `/etc/kubernetes/pki/ca-sai.crt`, restart kubelet. Chẩn đoán và sửa.
:::sol
```bash

systemctl restart kubelet ; exit ; exit

```
:::end

:::sol

```bash
ssh node01 'sudo journalctl -u kubelet --no-pager | tail -5'   # container runtime ... not ready / connection refused containerd.sock
```

# L: Sự cố mạng và Service

## Quy trình từ ngoài vào trong
```text
client → (Ingress/Gateway) → Service → EndpointSlice → Pod IP:targetPort → container port
```
```bash
# 1. Pod có chạy và Ready không, đang nghe port nào?
kubectl get po -l app=web -o wide
kubectl exec <pod> -- ss -tlnp 2>/dev/null || kubectl exec <pod> -- netstat -tlnp
# 2. Gọi thẳng IP pod
kubectl run t --image=busybox:1.36 --rm -it --restart=Never -- wget -qO- -T 3 <pod-ip>:<port>
# 3. Service có endpoint không? port/targetPort đúng không?
kubectl get svc web -o yaml | grep -A5 ports
kubectl get endpointslices -l kubernetes.io/service-name=web
# 4. Gọi bằng ClusterIP rồi bằng tên DNS
kubectl run t --image=busybox:1.36 --rm -it --restart=Never -- wget -qO- -T 3 web.<ns>
# 5. DNS
kubectl run t --image=busybox:1.36 --rm -it --restart=Never -- nslookup web.<ns>
# 6. NetworkPolicy chặn?
kubectl get netpol -A
# 7. kube-proxy và CNI còn chạy?
kubectl get po -n kube-system -o wide | grep -E 'proxy|calico|cilium|flannel|coredns'
```
| Triệu chứng | Nghi ngờ |
|---|---|
| Endpoints rỗng | selector sai, pod không Ready |
| Có endpoint nhưng timeout | targetPort sai, NetworkPolicy, kube-proxy |
| Gọi IP được, gọi tên không được | CoreDNS, sai namespace trong tên |
| Pod khác node không gọi được nhau | CNI, `ip_forward`, firewall giữa node |

:::ex
Tạo deployment `net-ts` (nginx) và Service với `targetPort: 8080` (sai, nginx nghe 80). Chẩn đoán theo quy trình và sửa.
:::sol
```bash
kubectl create deploy net-ts --image=nginx
kubectl expose deploy net-ts --port=80 --target-port=8080
kubectl run t --image=busybox:1.36 --rm -it --restart=Never -- wget -qO- -T 3 net-ts   # connection refused
kubectl get endpointslices -l kubernetes.io/service-name=net-ts   # endpoint ...:8080
kubectl patch svc net-ts -p '{"spec":{"ports":[{"port":80,"targetPort":80}]}}'
```
:::end

:::ex
(Lab) Xoá DaemonSet kube-proxy (sau khi backup YAML). Service mới còn hoạt động không? Khôi phục.
:::sol
```bash

kubectl delete ds kube-proxy -n kube-system
# Service cũ có thể vẫn chạy (luật iptables còn), Service mới tạo sau đó không có luật → không truy cập được

```
:::end

# L: Giám sát và log

## metrics-server và kubectl top
```bash
kubectl top nodes
kubectl top po -A --sort-by=cpu
kubectl top po -n prod --sort-by=memory --containers
```
Đề dạng: "Tìm pod dùng nhiều CPU nhất có label X, ghi tên vào file":
```bash
kubectl top po -l app=api -A --sort-by=cpu --no-headers | head -1 | awk '{print $2}' > /root/top-cpu.txt
# với -A, cột 1 là NAMESPACE, cột 2 là NAME
```

## Log
- Container ghi log ra stdout/stderr → runtime lưu ở `/var/log/pods/<ns>_<pod>_<uid>/<container>/0.log`, symlink trong `/var/log/containers/`.
- `kubectl logs` đọc file đó qua kubelet.
```bash
kubectl logs deploy/web                       # một pod của deployment
kubectl logs -l app=web --all-containers --prefix
kubectl logs web --since=10m --timestamps
kubectl logs web -c sidecar -f
```
- Log của kubelet, containerd: `journalctl`. Log control plane (static pod): `kubectl logs -n kube-system` hoặc `crictl logs`.

## Debug nâng cao
```bash
kubectl debug -it <pod> --image=busybox:1.36 --target=<container>   # container tạm trong pod đang chạy
kubectl debug node/node01 -it --image=ubuntu                        # shell trên node (host ở /host)
kubectl port-forward svc/web 8080:80                                 # truy cập Service từ máy mình
kubectl cp <pod>:/etc/nginx/nginx.conf ./nginx.conf
```

:::ex
Ghi tên node đang dùng nhiều memory nhất vào `/root/top-node.txt`.
:::sol
```bash
kubectl top nodes --sort-by=memory --no-headers | head -1 | awk '{print $1}' > /root/top-node.txt
```
:::end

:::ex
Pod `app` có 2 container `main` và `logger`. Lấy các dòng chứa "ERROR" trong log của `logger` trong 1 giờ qua, ghi vào `/root/errors.log`.
:::sol
```bash
kubectl logs app -c logger --since=1h | grep ERROR > /root/errors.log
```
:::end

