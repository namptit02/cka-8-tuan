# L: Linux 1 – Shell, cây thư mục, điều hướng

## Shell là gì
Khi mở terminal, bạn đang nói chuyện với **shell** (trên Ubuntu là `bash`). Shell đọc lệnh bạn gõ, chạy chương trình tương ứng rồi in kết quả. Một lệnh có dạng:

```bash
lệnh  [tuỳ chọn]  [tham số]
ls    -la         /etc
```

- Tuỳ chọn ngắn dùng 1 gạch và gộp được: `-l -a` = `-la`. Tuỳ chọn dài dùng 2 gạch: `--all`.
- `Tab` để tự hoàn thành tên lệnh/file. Bấm `Tab` 2 lần để xem các lựa chọn. Trong phòng thi điều này tiết kiệm rất nhiều thời gian.
- `↑` để gọi lại lệnh cũ, `Ctrl+R` để tìm trong lịch sử, `Ctrl+C` dừng lệnh đang chạy, `Ctrl+L` xoá màn hình.
- Xem hướng dẫn: `man ls`, `ls --help`. Thoát `man` bằng `q`.

## Cây thư mục Linux
Mọi thứ bắt đầu từ gốc `/`. Những thư mục bạn sẽ gặp khi làm Kubernetes:

| Thư mục | Chứa gì | Ví dụ liên quan K8s |
|---|---|---|
| `/etc` | File cấu hình hệ thống | `/etc/kubernetes/`, `/etc/containerd/config.toml` |
| `/var` | Dữ liệu thay đổi: log, database | `/var/lib/etcd`, `/var/lib/kubelet`, `/var/log/pods` |
| `/home/<user>` | Thư mục của người dùng | `~/.kube/config` |
| `/root` | Thư mục của user root | Đề thi hay bắt ghi file vào `/root/...` |
| `/usr/bin`, `/usr/local/bin` | Chương trình | `kubectl`, `kubeadm`, `etcdctl` |
| `/opt` | Phần mềm cài thêm | `/opt/cni/bin` (plugin CNI) |
| `/tmp` | File tạm, xoá khi reboot | |
| `/proc`, `/sys` | File ảo, thông tin kernel | `/proc/sys/net/ipv4/ip_forward` |
| `/run` | Socket, PID file lúc chạy | `/run/containerd/containerd.sock` |

## Đường dẫn
- **Tuyệt đối**: bắt đầu bằng `/`, ví dụ `/etc/kubernetes/manifests`.
- **Tương đối**: tính từ thư mục hiện tại, ví dụ `manifests/etcd.yaml`.
- `.` là thư mục hiện tại, `..` là thư mục cha, `~` là home của bạn, `-` là thư mục vừa ở trước đó (`cd -`).

```bash
pwd                     # đang ở đâu
cd /etc/kubernetes      # đi tới đường dẫn tuyệt đối
cd manifests            # đi tiếp bằng đường dẫn tương đối
cd ..                   # lên 1 cấp
cd ~  hoặc  cd          # về home
cd -                    # quay lại chỗ trước
ls -la                  # liệt kê cả file ẩn (bắt đầu bằng .), dạng chi tiết
ls -lh /var/log         # kích thước dễ đọc (K, M, G)
ls -ltr                 # sắp theo thời gian, mới nhất ở cuối
tree -L 2 /etc/kubernetes   # xem dạng cây (có thể phải cài: apt install tree)
```

## Đọc kết quả `ls -l`
```text
-rw-------  1 root root 5652 Jan 10 09:00 admin.conf
drwxr-xr-x  2 root root 4096 Jan 10 09:00 manifests
lrwxrwxrwx  1 root root   30 Jan 10 09:00 current -> /var/lib/x
```
Ký tự đầu: `-` file thường, `d` thư mục, `l` symlink. 9 ký tự tiếp theo là quyền (học ở bài Quyền). Sau đó là chủ sở hữu, nhóm, kích thước, thời gian, tên.

:::ex
Liệt kê nội dung `/etc/kubernetes` (kể cả file ẩn) dạng chi tiết, rồi đi vào thư mục `manifests` bằng đường dẫn tương đối và in ra đường dẫn hiện tại.
:::sol
```bash
ls -la /etc/kubernetes
cd /etc/kubernetes
cd manifests
pwd        # /etc/kubernetes/manifests
```
:::end

:::ex
Không dùng `cd`, liệt kê 5 file log được sửa gần nhất trong `/var/log`.
:::sol
```bash
ls -lt /var/log | head -6     # dòng đầu là "total ...", nên lấy 6
```
:::end

:::ex
Tìm xem lệnh `kubectl` nằm ở đâu trên máy và nó là file hay symlink.
:::sol
```bash
which kubectl          # ví dụ /usr/bin/kubectl
ls -l $(which kubectl)
type kubectl           # cũng cho biết nếu là alias
```
:::end

# L: Linux 2 – Làm việc với file, redirect và pipe

## Tạo, sao chép, di chuyển, xoá
```bash
touch a.txt                 # tạo file rỗng (hoặc cập nhật thời gian)
mkdir -p lab/w1/day1        # -p: tạo cả thư mục cha nếu chưa có
cp a.txt lab/               # copy file
cp -r lab lab-backup        # copy thư mục (đệ quy)
cp etcd.yaml etcd.yaml.bak  # LUÔN backup trước khi sửa manifest control plane
mv a.txt b.txt              # đổi tên
mv b.txt lab/               # di chuyển
rm b.txt                    # xoá file
rm -r lab-backup            # xoá thư mục
rm -rf thu-muc              # xoá không hỏi — cẩn thận!
ln -s /opt/app/v2 /opt/app/current   # tạo symlink
```

## Xem nội dung
```bash
cat file.yaml          # in toàn bộ
less file.yaml         # xem từng trang: Space xuống, b lên, /từ tìm, q thoát
head -20 file          # 20 dòng đầu
tail -20 file          # 20 dòng cuối
tail -f /var/log/syslog   # theo dõi file đang được ghi thêm (Ctrl+C để thoát)
wc -l file             # đếm số dòng
diff a.yaml b.yaml     # so sánh 2 file
```

## Tìm file
```bash
find /etc -name "*.conf"               # theo tên
find / -name "kubelet*" 2>/dev/null    # cả máy, bỏ lỗi "Permission denied"
find /var/log -mmin -10                # sửa trong 10 phút qua
find /tmp -type f -size +10M           # file lớn hơn 10MB
```

## Redirect: đưa kết quả vào file
Mỗi chương trình có 3 luồng: **stdin (0)**, **stdout (1)** – kết quả bình thường, **stderr (2)** – thông báo lỗi.

| Cú pháp | Ý nghĩa |
|---|---|
| `cmd > f` | ghi stdout vào f (ghi đè) |
| `cmd >> f` | ghi nối thêm vào cuối f |
| `cmd 2> f` | ghi stderr vào f |
| `cmd > f 2>&1` | ghi cả stdout và stderr vào f |
| `cmd 2>/dev/null` | vứt bỏ lỗi |
| `cmd < f` | lấy f làm đầu vào |

Đề CKA rất hay có dạng *"ghi kết quả vào /opt/output.txt"* → dùng `>`.

## Pipe `|`: nối lệnh
Đầu ra của lệnh trước là đầu vào của lệnh sau:
```bash
kubectl get pods -A | grep -v Running        # pod không ở trạng thái Running
kubectl get pods -A | wc -l
cat /etc/passwd | sort | head
kubectl get nodes | tee /root/nodes.txt      # vừa in ra màn hình vừa ghi file
```

## Heredoc: tạo file nhiều dòng không cần vim
```bash
cat <<EOF > pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: test
spec:
  containers:
  - name: c
    image: nginx
EOF

kubectl apply -f - <<EOF     # apply thẳng, không cần file
apiVersion: v1
kind: Namespace
metadata:
  name: demo
EOF
```

:::ex
Tạo thư mục `~/w1/files`, trong đó tạo file `hello.txt` chứa 2 dòng "xin chao" và "kubernetes" (không dùng vim). Sau đó đếm số dòng.
:::sol
```bash
mkdir -p ~/w1/files && cd ~/w1/files
echo "xin chao" > hello.txt
echo "kubernetes" >> hello.txt
wc -l hello.txt          # 2 hello.txt
```
:::end

:::ex
Chạy `ls /khong-ton-tai /etc/hostname`. Ghi phần kết quả đúng vào `ok.txt` và phần lỗi vào `err.txt`.
:::sol

```bash
cat ok.txt     # /etc/hostname
cat err.txt    # ls: cannot access '/khong-ton-tai'...
```
:::end

:::ex
Tìm mọi file `.yaml` trong `/etc/kubernetes` và ghi danh sách vào `/root/yaml-list.txt`, sau đó đếm có bao nhiêu file.
:::sol
```bash

wc -l /root/yaml-list.txt
```
:::end

:::ex
Dùng heredoc tạo file `/root/ns.yaml` định nghĩa namespace `w1`, rồi apply nó.
:::sol

# L: Linux 3 – Xử lý text: grep, awk, sort, sed

Kết quả `kubectl` là text dạng bảng. Biết lọc text giúp bạn trả lời nhanh các câu "ghi tên X vào file".

## grep – lọc dòng
```bash
grep error app.log              # dòng chứa "error"
grep -i error app.log           # không phân biệt hoa thường
grep -v Running                 # dòng KHÔNG chứa
grep -n image pod.yaml          # kèm số dòng
grep -r "pod-network-cidr" /etc/kubernetes   # tìm đệ quy trong thư mục
grep -E "Error|Failed"          # nhiều mẫu (regex mở rộng)
grep -A3 -B1 Events             # kèm 3 dòng sau, 1 dòng trước
grep -c Running                 # chỉ đếm số dòng khớp
```

## awk – lấy cột
awk tách dòng theo khoảng trắng; `$1` là cột 1, `$NF` là cột cuối.
```bash
kubectl get pods --no-headers | awk '{print $1}'          # tên pod
kubectl get pods --no-headers | awk '$3!="Running"{print $1}'   # pod không Running
kubectl get nodes --no-headers | awk '{print $1, $2}'
awk -F: '{print $1}' /etc/passwd       # -F đổi ký tự phân tách
```

## cut, sort, uniq, head
```bash
cut -d: -f1 /etc/passwd             # cột 1, phân tách bằng ":"
sort file ; sort -r ; sort -n       # sắp xếp chữ / ngược / số
sort -k3 -n                         # theo cột 3 dạng số
uniq -c                             # đếm dòng trùng liên tiếp (thường sort trước)
kubectl get pods -A --no-headers | awk '{print $1}' | sort | uniq -c   # số pod mỗi namespace
```

## sed – thay thế
```bash
sed 's/old/new/' f        # thay lần đầu mỗi dòng, in ra màn hình
sed 's/old/new/g' f       # thay mọi lần
sed -i 's/1.34/1.35/g' f  # -i: sửa trực tiếp file
sed -n '10,20p' f         # in dòng 10–20
```

## base64 – đọc Secret
Secret trong K8s được lưu dạng base64 (đây là mã hoá để truyền, **không phải bảo mật**):
```bash
echo -n "s3cr3t" | base64            # czNjcjN0  (-n để không thêm xuống dòng)
echo czNjcjN0 | base64 -d            # s3cr3t
kubectl get secret db -o jsonpath='{.data.password}' | base64 -d
```

:::ex
Từ `kubectl get pods -A`, in ra tên namespace và tên pod của những pod **không** ở trạng thái Running.
:::sol
```bash
kubectl get pods -A --no-headers | awk '$4!="Running"{print $1, $2}'
# Cột: NAMESPACE NAME READY STATUS ... nên STATUS là $4
```
:::end

:::ex
Đếm số pod trong mỗi namespace, sắp xếp giảm dần.
:::sol
```bash
kubectl get pods -A --no-headers | awk '{print $1}' | sort | uniq -c | sort -rn
```
:::end

:::ex
Trong file `/etc/kubernetes/manifests/kube-apiserver.yaml`, tìm dòng chứa `service-cluster-ip-range` và ghi giá trị CIDR (chỉ phần sau dấu `=`) vào `/root/svc-cidr.txt`.
:::sol
```bash
grep service-cluster-ip-range /etc/kubernetes/manifests/kube-apiserver.yaml
grep service-cluster-ip-range /etc/kubernetes/manifests/kube-apiserver.yaml | cut -d= -f2 > /root/svc-cidr.txt
cat /root/svc-cidr.txt     # ví dụ 10.96.0.0/12
```
:::end

:::ex
Tạo file `app.conf` có dòng `mode=dev`. Dùng sed đổi thành `mode=prod` ngay trong file.
:::sol
```bash
echo "mode=dev" > app.conf
sed -i 's/mode=dev/mode=prod/' app.conf
cat app.conf
```
:::end

:::ex
Giải mã chuỗi base64 `YWRtaW4=` và mã hoá chuỗi `P@ssw0rd`.
:::sol
```bash
echo YWRtaW4= | base64 -d          # admin
echo -n 'P@ssw0rd' | base64        # UEBzc3cwcmQ=
```
:::end

# L: Linux 4 – Vim cho YAML

Trong phòng thi bạn sẽ sửa YAML liên tục. Vim có sẵn trên mọi máy; nano có thể có, nhưng nên quen vim.

## Các chế độ (mode)
- **Normal** (mặc định khi mở): di chuyển, xoá, copy. Bấm `Esc` để về đây.
- **Insert**: gõ chữ. Vào bằng `i` (trước con trỏ), `a` (sau), `o` (dòng mới bên dưới), `O` (dòng mới bên trên).
- **Visual**: chọn vùng. `v` theo ký tự, `V` theo dòng, `Ctrl+v` theo khối cột.
- **Command**: gõ `:` từ Normal.

## Lệnh phải thuộc
| Phím | Tác dụng |
|---|---|
| `:w` `:q` `:wq` `:q!` | lưu, thoát, lưu+thoát, thoát không lưu |
| `h j k l` | trái, xuống, lên, phải (mũi tên cũng được) |
| `gg` / `G` / `:25` | đầu file / cuối file / tới dòng 25 |
| `0` / `$` / `w` / `b` | đầu dòng / cuối dòng / từ sau / từ trước |
| `dd` / `5dd` | xoá (cắt) 1 dòng / 5 dòng |
| `yy` / `5yy` | copy 1 / 5 dòng |
| `p` / `P` | dán dưới / trên |
| `x` | xoá 1 ký tự |
| `cw` | thay từ (xoá từ và vào Insert) |
| `u` / `Ctrl+r` | undo / redo |
| `/image` rồi `n` / `N` | tìm, kết quả tiếp / trước |
| `:%s/nginx:1.27/nginx:1.28/g` | thay thế toàn file |
| `V` chọn dòng → `>` hoặc `<` | thụt vào / ra |
| `.` | lặp lại thao tác vừa làm |

## Cấu hình cho YAML
YAML **cấm tab**, dùng 2 dấu cách cho mỗi cấp. Đầu giờ thi chạy:
```bash
cat <<EOF >> ~/.vimrc
set expandtab
set tabstop=2
set shiftwidth=2
set number
EOF
```
- Khi dán YAML từ docs mà bị thụt lề bậc thang: trong vim gõ `:set paste`, vào Insert rồi dán, sau đó `:set nopaste`.
- Sau khi sửa xong, kiểm tra cú pháp nhanh: `kubectl apply -f file.yaml --dry-run=client`.

## Cấu trúc YAML cơ bản
```yaml
key: value            # map
list:                 # danh sách: mỗi phần tử bắt đầu bằng "- "
- a
- b
containers:
- name: web           # danh sách các map
  image: nginx
  ports:
  - containerPort: 80
command: ["sleep", "3600"]   # dạng ngắn của danh sách
labels: {app: web, tier: fe} # dạng ngắn của map
```

:::ex
Chạy `vimtutor` và làm hết bài 1–3 (khoảng 20 phút). Đây là bài tập bắt buộc của tuần 1.
:::sol
```bash
vimtutor
```
Làm lại lần 2 vào cuối tuần, mục tiêu không cần nhìn hướng dẫn.
:::end

:::ex
Tạo `deploy.yaml` bằng lệnh `kubectl create deploy web --image=nginx:1.27 --replicas=2 --dry-run=client -o yaml > deploy.yaml`. Mở bằng vim và: (1) đổi image sang `nginx:1.28` bằng lệnh thay thế, (2) xoá dòng `status: {}`, (3) xoá dòng `creationTimestamp: null`, (4) đổi replicas sang 4. Apply thử với `--dry-run=client`.
:::sol
```text

:%s/nginx:1.27/nginx:1.28/g
/status       -> dd
/creationTimestamp  -> dd  (làm 2 lần vì có 2 dòng)
/replicas     -> di chuyển tới số 2, bấm x, i, gõ 4, Esc
:wq
```
```bash
kubectl apply -f deploy.yaml --dry-run=client
```
:::end

:::ex
Copy khối `containers` trong file pod và tạo container thứ hai tên `sidecar` image `busybox`, chạy lệnh `sleep 3600`.
:::sol
```text
Đặt con trỏ ở dòng "- image: nginx" (hoặc "- name: ..."), V chọn các dòng của container đầu, y,
di chuyển xuống cuối khối, p. Sửa name và image, thêm dòng:
    command: ["sleep", "3600"]
```
Kết quả:
```yaml
  containers:
  - name: web
    image: nginx
  - name: sidecar
    image: busybox
    command: ["sleep", "3600"]
```
:::end

# L: Linux 5 – User, sudo và quyền file

## User và root
- **root** là user có toàn quyền. Trong đề thi bạn vào máy bằng user thường, sau đó SSH sang node và thường cần `sudo -i` để thành root.
- `whoami`, `id` – xem bạn là ai, thuộc nhóm nào.
- `sudo lệnh` – chạy 1 lệnh với quyền root. `sudo -i` – mở shell root (dấu nhắc đổi từ `$` sang `#`). `exit` để quay lại.
- Thêm user: `useradd -m dev`, `passwd dev`, cho vào nhóm: `usermod -aG sudo dev`.

## Quyền file
```text
-rwxr-x---  1 alice devs  app.sh
 └┬┘└┬┘└┬┘
 user group others
```
`r` đọc (4), `w` ghi (2), `x` thực thi (1). Với thư mục, `x` nghĩa là được `cd` vào.

| Số | Quyền | Hay gặp |
|---|---|---|
| 755 | rwxr-xr-x | script, thư mục |
| 644 | rw-r--r-- | file cấu hình thường |
| 600 | rw------- | khoá riêng, kubeconfig (`admin.conf`) |
| 700 | rwx------ | thư mục `~/.ssh` |

```bash
chmod 600 ~/.kube/config
chmod +x script.sh            # thêm quyền chạy
chmod u+w,o-r file            # dạng ký hiệu
chown alice:devs file         # đổi chủ và nhóm
chown -R alice ~/project      # đệ quy
```

## Liên hệ Kubernetes
- Sau `kubeadm init`, bạn copy kubeconfig cho user thường:
```bash
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
```
- `securityContext.runAsUser: 1000` trong Pod chính là UID Linux mà process trong container chạy dưới đó.

:::ex
Tạo file `secret.key`, đặt quyền chỉ chủ sở hữu được đọc/ghi. Kiểm tra bằng `ls -l`.
:::sol
```bash
touch secret.key
chmod 600 secret.key
ls -l secret.key      # -rw-------
```
:::end

:::ex
Viết script `hi.sh` in ra "hello", cho phép chạy được và chạy nó.
:::sol
```bash
echo 'echo hello' > hi.sh
chmod +x hi.sh
./hi.sh
```
:::end

:::ex
Bạn không đọc được `/etc/kubernetes/admin.conf`. Vì sao, và làm sao dùng file đó với kubectl?
:::sol
File có quyền 600, chủ là root. Cách xử lý:
```bash
ls -l /etc/kubernetes/admin.conf
sudo kubectl --kubeconfig /etc/kubernetes/admin.conf get nodes
# hoặc copy về ~/.kube/config như phần lý thuyết
```
:::end

# L: Linux 6 – Process, systemd và journalctl

Đây là bài **quan trọng nhất** của tuần 1 cho phần Troubleshooting: kubelet và containerd đều là service của systemd.

## Process
```bash
ps aux                       # mọi process
ps aux | grep kube           # tìm process kubelet, apiserver...
ps -ef --forest              # xem dạng cây cha-con
top   (hoặc htop)            # theo dõi CPU/RAM, q để thoát
kill 1234                    # gửi SIGTERM (15): xin process dừng tử tế
kill -9 1234                 # SIGKILL (9): giết ngay, không cho dọn dẹp
pgrep -a kubelet             # tìm PID theo tên
```
Liên hệ K8s: khi xoá pod, kubelet gửi **SIGTERM**, đợi `terminationGracePeriodSeconds` (mặc định 30s), quá hạn thì gửi **SIGKILL**. Exit code 137 = 128 + 9 nghĩa là bị SIGKILL (thường do OOM).

## systemd và systemctl
systemd là process số 1, quản lý các **service** (unit).
```bash
systemctl status kubelet          # trạng thái, PID, vài dòng log cuối
systemctl start|stop|restart kubelet
systemctl enable kubelet          # tự chạy khi boot
systemctl enable --now kubelet    # enable + start luôn
systemctl disable kubelet
systemctl is-active kubelet ; systemctl is-enabled kubelet
systemctl list-units --type=service --state=failed
systemctl cat kubelet             # xem unit file và các drop-in
```

## Unit file và drop-in
Unit file mô tả cách chạy service. Kubelet trên máy cài bằng kubeadm:
```text
/usr/lib/systemd/system/kubelet.service                    # unit chính
/usr/lib/systemd/system/kubelet.service.d/10-kubeadm.conf  # drop-in thêm cờ
/var/lib/kubelet/config.yaml                               # cấu hình kubelet
/var/lib/kubelet/kubeadm-flags.env                         # cờ do kubeadm sinh
```
(Trên một số bản cài, drop-in nằm ở `/etc/systemd/system/kubelet.service.d/`. Dùng `systemctl cat kubelet` để biết chắc.)

Một unit file đơn giản:
```ini
[Unit]
Description=My app
After=network.target

[Service]
ExecStart=/usr/local/bin/myapp --port 8080
Restart=always

[Install]
WantedBy=multi-user.target
```
**Sau khi sửa bất kỳ unit file nào: `systemctl daemon-reload` rồi `systemctl restart <service>`.**

# L: Linux 7 – Mạng cơ bản

## Khái niệm
- **IP**: địa chỉ của một giao diện mạng, ví dụ `192.168.1.10`.
- **CIDR**: `10.244.0.0/16` nghĩa là 16 bit đầu cố định → dải từ 10.244.0.0 đến 10.244.255.255 (65.536 địa chỉ). `/24` = 256 địa chỉ, `/32` = 1 địa chỉ.
- **Port**: một IP có nhiều dịch vụ, phân biệt bằng port. Port K8s cần nhớ: `6443` apiserver, `2379-2380` etcd, `10250` kubelet, `10257` controller-manager, `10259` scheduler, `30000-32767` NodePort.
- **DNS**: đổi tên thành IP. Máy dùng nameserver trong `/etc/resolv.conf`. Pod cũng có `/etc/resolv.conf` trỏ tới CoreDNS.
- **Gateway / route**: gói tin tới mạng khác đi qua đâu.
- **NAT, iptables**: kernel viết lại/chặn gói tin. kube-proxy dùng iptables (hoặc IPVS/nftables) để thực hiện Service.

Trong K8s có 3 dải IP **không được trùng nhau**: IP của node, Pod CIDR (ví dụ `10.244.0.0/16`), Service CIDR (mặc định `10.96.0.0/12`).

## Lệnh
```bash

ip route                      # bảng định tuyến, dòng "default via" là gateway
hostname -I                   # các IP của máy
ss -tlnp                      # port TCP đang lắng nghe + process
ss -tlnp | grep 6443
curl -k https://localhost:6443/healthz      # -k bỏ qua kiểm tra cert
curl -v http://10.96.0.10                   # -v xem chi tiết
curl -s -o /dev/null -w "%{http_code}" http://svc   # chỉ lấy mã HTTP
nc -zv 10.0.0.5 6443          # kiểm tra port có mở không
ping -c 3 8.8.8.8
nslookup kubernetes.default   # tra DNS
dig +short google.com
cat /etc/hosts /etc/resolv.conf
```

## sysctl và module kernel cho K8s
```bash
# Module cần cho mạng bridge của container
cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF
sudo modprobe overlay && sudo modprobe br_netfilter
lsmod | grep br_netfilter

# Tham số kernel
cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.ipv4.ip_forward = 1
net.bridge.bridge-nf-call-iptables = 1
net.bridge.bridge-nf-call-ip6tables = 1
EOF
sudo sysctl --system
sysctl net.ipv4.ip_forward      # = 1
```
`ip_forward = 1` cho phép node chuyển tiếp gói tin giữa các pod/node. Thiếu nó, mạng pod hỏng.

:::ex
Dải `10.244.0.0/16` có bao nhiêu địa chỉ? `10.244.1.0/24` có nằm trong dải đó không? `10.96.0.0/12` kết thúc ở địa chỉ nào?
:::sol
- `/16` → 2^16 = 65.536 địa chỉ.
- Có, vì 10.244.1.x nằm trong 10.244.0.0–10.244.255.255. (Mỗi node thường được cấp một `/24` con trong Pod CIDR.)
- `/12`: 12 bit đầu cố định. Octet thứ 2 là 96 = 0110 0000, 4 bit đầu cố định → chạy tới 0110 1111 = 111. Dải: 10.96.0.0 – 10.111.255.255.
:::end

:::ex
Trên control plane, xác định process nào đang lắng nghe port 6443, 2379 và 10250.
:::sol
```bash
sudo ss -tlnp | grep -E '6443|2379|10250'
# 6443 -> kube-apiserver, 2379 -> etcd, 10250 -> kubelet
```
:::end

:::ex
Kiểm tra apiserver còn sống bằng curl, không dùng kubectl.
:::sol
```bash
curl -k https://localhost:6443/livez     # ok
curl -k https://localhost:6443/readyz?verbose
```
:::end

:::ex
Bật vĩnh viễn `net.ipv4.ip_forward` trên một máy mới và xác nhận.
:::sol
```bash

sudo sysctl --system
sysctl net.ipv4.ip_forward
cat /proc/sys/net/ipv4/ip_forward   # 1
```
:::end

# L: Linux 9 – Bổ sung: signal, ổ đĩa, drop-in, find/tar, mạng, journalctl nâng cao

Bài này lấp các chủ đề hay xuất hiện trong phần Troubleshooting mà 8 bài trước mới nói qua.

## Signal và kill
| Signal | Số | Ý nghĩa | Liên quan K8s |
|---|---|---|---|
| SIGTERM | 15 | xin dừng tử tế (mặc định của `kill`) | kubelet gửi khi xoá pod |
| SIGKILL | 9 | giết ngay, **không thể bỏ qua** | gửi sau `terminationGracePeriodSeconds`; OOM killer |
| SIGINT | 2 | Ctrl+C | |
| SIGHUP | 1 | "đọc lại cấu hình" với nhiều daemon | |

Exit code khi bị signal = **128 + số signal**: 130 (Ctrl+C), 137 (SIGKILL/OOM), 143 (SIGTERM).
```bash
kill -l                      # danh sách signal
pgrep -a sleep               # PID + dòng lệnh
kill 1234 ; kill -9 1234     # TERM rồi KILL
pkill -f "python3 -m http"   # theo dòng lệnh
sleep 300 &                  # chạy nền; jobs ; fg %1 ; Ctrl+Z ; bg
nohup cmd > out.log 2>&1 &   # chạy tiếp sau khi thoát SSH
```

# L: Docker 1 – Container là gì

## Container vs máy ảo
- **Máy ảo (VM)**: mỗi VM có kernel riêng, chạy trên hypervisor. Nặng (GB), khởi động chậm (phút).
- **Container**: chỉ là **một process Linux bình thường** được kernel cách ly và giới hạn tài nguyên. Dùng chung kernel với máy chủ. Nhẹ (MB), khởi động trong giây.

Container được làm từ 2 tính năng của kernel Linux:

**1. Namespaces – cách ly "nhìn thấy gì"**
| Namespace | Cách ly |
|---|---|
| PID | process chỉ thấy các process trong container, process chính có PID 1 |
| NET | có card mạng, IP, port riêng |
| MNT | có hệ thống file riêng (từ image) |
| UTS | hostname riêng |
| IPC | bộ nhớ chia sẻ riêng |
| USER | ánh xạ UID riêng |

Trong K8s, **các container trong cùng 1 Pod dùng chung NET namespace** → chung IP, gọi nhau qua `localhost`.

**2. cgroups – giới hạn "dùng bao nhiêu"**
CPU, RAM, I/O. `resources.limits.memory: 256Mi` trong Pod được kubelet chuyển thành giới hạn cgroup. Vượt RAM → kernel giết process (OOMKilled).

## Image
- **Image** là gói chỉ-đọc chứa hệ thống file + metadata (lệnh chạy mặc định, biến môi trường, port).
- Image gồm nhiều **layer** xếp chồng. Mỗi lệnh trong Dockerfile tạo 1 layer. Layer được chia sẻ giữa các image → tiết kiệm dung lượng.
- Khi chạy, container thêm 1 layer **ghi được** ở trên cùng. Xoá container là mất layer này → cần **volume** để giữ dữ liệu.
- Tên image: `[registry/][namespace/]tên[:tag]`.
  - `nginx` = `docker.io/library/nginx:latest`
  - `registry.k8s.io/kube-apiserver:v1.35.0`
  - `quay.io/calico/node:v3.30.0`
- Không ghi tag = `latest`. Trong K8s nên luôn ghi tag cụ thể.

## Chuẩn OCI và "ai chạy container"
```text
Docker CLI ─► dockerd ─► containerd ─► runc ─► process
kubelet ──CRI──► containerd ─► runc ─► process
kubelet ──CRI──► cri-dockerd ─► dockerd ─► containerd ─► runc
```
- **OCI**: chuẩn chung cho định dạng image và cách chạy. Image build bằng Docker chạy được trên containerd và ngược lại.
- **runc**: chương trình cấp thấp thực sự tạo namespace/cgroup.
- **containerd / CRI-O**: runtime cấp cao, quản lý image và vòng đời container.
- **CRI (Container Runtime Interface)**: API mà kubelet dùng để nói chuyện với runtime qua socket, ví dụ `unix:///run/containerd/containerd.sock`.
- Từ K8s 1.24, kubelet bỏ "dockershim" → muốn dùng Docker Engine phải có **cri-dockerd**. Hầu hết cluster dùng containerd.

**Kết luận cho CKA**: bạn không cần Docker trên node, nhưng cần hiểu image/container và dùng `crictl`.

:::ex
Giải thích ngắn: (a) tại sao 2 container trong cùng một Pod gọi nhau được qua `localhost`? (b) Exit code 137 kèm OOMKilled liên quan tới tính năng nào của kernel?
:::sol
(a) Chúng dùng chung network namespace của Pod (do container "pause" giữ), nên chung IP và chung `localhost`.
(b) cgroups: container vượt giới hạn memory của cgroup, kernel OOM killer gửi SIGKILL (128+9 = 137).
:::end

:::ex
Image `nginx` đầy đủ là gì? Image `registry.k8s.io/etcd:3.6.4-0` thuộc registry nào, tag là gì?
:::sol
- `docker.io/library/nginx:latest`
- Registry `registry.k8s.io`, tên `etcd`, tag `3.6.4-0`.
:::end

:::ex
Tự thấy "container chỉ là process": trên máy có Docker, chạy `docker run -d --name s busybox sleep 1000`, sau đó tìm process `sleep 1000` từ máy chủ bằng `ps`.
:::sol
```bash
docker run -d --name s busybox sleep 1000
ps aux | grep "sleep 1000"          # thấy process ngay trên máy chủ
docker exec s ps                    # trong container: sleep có PID 1
docker rm -f s
```
:::end

# L: Docker 2 – Thực hành Docker và Dockerfile

Cài Docker trên một VM Ubuntu để tập (không cài lên node K8s đang dùng containerd): `curl -fsSL https://get.docker.com | sh`.

## Vòng đời container
```bash
docker pull nginx:1.27
docker images
docker run -d --name web -p 8080:80 nginx:1.27   # -d chạy nền, -p hostPort:containerPort
docker ps            # đang chạy
docker ps -a         # cả đã dừng
curl localhost:8080
docker logs web      # ≈ kubectl logs
docker logs -f web
docker exec -it web sh       # ≈ kubectl exec -it web -- sh
docker inspect web           # JSON chi tiết: IP, mount, env
docker stop web ; docker start web
docker rm -f web
docker run -it --rm busybox sh    # --rm: tự xoá khi thoát
```

## Biến môi trường, volume, mạng
```bash
docker run -d -e MYSQL_ROOT_PASSWORD=pw --name db mysql:8      # ≈ env trong Pod
docker run -d -v /data/html:/usr/share/nginx/html nginx        # bind mount ≈ hostPath
docker volume create vol1 ; docker run -v vol1:/data busybox   # named volume ≈ PVC
docker network create app-net
docker run -d --network app-net --name api my-api
docker run --network app-net busybox wget -qO- http://api      # gọi theo tên ≈ DNS Service
```

## Dockerfile
```dockerfile
FROM python:3.12-slim           # image gốc
WORKDIR /app                    # thư mục làm việc
COPY requirements.txt .
RUN pip install -r requirements.txt   # chạy lúc BUILD, tạo layer
COPY . .
ENV PORT=8000
EXPOSE 8000                     # chỉ là ghi chú tài liệu
ENTRYPOINT ["python"]           # chương trình chạy
CMD ["app.py"]                  # tham số mặc định
```
```bash
docker build -t myapp:v1 .
docker run -d -p 8000:8000 myapp:v1
docker tag myapp:v1 registry.example.com/team/myapp:v1
docker push registry.example.com/team/myapp:v1
```

## ENTRYPOINT/CMD ↔ command/args (rất hay nhầm)
| Docker | Kubernetes | Ghi đè |
|---|---|---|
| `ENTRYPOINT` | `command` | chương trình |
| `CMD` | `args` | tham số |

```yaml
containers:
- name: c
  image: busybox
  command: ["sh", "-c"]               # thay ENTRYPOINT
  args: ["echo hello; sleep 3600"]    # thay CMD
```
`kubectl run x --image=busybox -- sleep 3600` → đặt **args**. Thêm `--command` → đặt **command**.

:::ex
Chạy nginx ở cổng 8081 trên máy, sửa trang chủ thành "CKA" bằng `docker exec`, kiểm tra bằng curl, xem log, rồi xoá container.
:::sol
```bash
docker run -d --name web -p 8081:80 nginx
docker exec web sh -c 'echo CKA > /usr/share/nginx/html/index.html'
curl localhost:8081        # CKA
docker logs web
docker rm -f web
```
:::end

:::ex
Viết Dockerfile từ `busybox` in ra `hello from <HOSTNAME>` mỗi 5 giây. Build thành `hello:v1` và chạy.
:::sol
```dockerfile
FROM busybox
CMD ["sh", "-c", "while true; do echo hello from $(hostname); sleep 5; done"]
```
```bash
docker build -t hello:v1 .
docker run -d --name h hello:v1
docker logs -f h
```
:::end

:::ex
Image `myapp` có `ENTRYPOINT ["python"]` và `CMD ["app.py"]`. Viết phần container trong Pod để chạy `python worker.py --debug`.
:::sol
Chỉ cần ghi đè CMD:
```yaml
containers:
- name: worker
  image: myapp:v1
  args: ["worker.py", "--debug"]
```
:::end

:::ex
Dữ liệu ghi trong container có còn sau khi `docker rm` không? Làm sao giữ lại? Trong K8s tương ứng là gì?
:::sol
Không, vì nó nằm ở layer ghi được của container. Dùng volume (`-v vol:/path`). Trong K8s tương ứng: `emptyDir` (sống theo Pod), `hostPath` (thư mục trên node), PersistentVolumeClaim (lưu trữ bền vững).
:::end

# L: Docker 3 – containerd và crictl trên node K8s

Trên node K8s thật bạn sẽ **không có lệnh docker**. Dùng:

## crictl – công cụ debug theo chuẩn CRI
```bash
crictl ps                    # container đang chạy (≈ docker ps)
crictl ps -a                 # cả container đã chết — dùng khi apiserver crash
crictl pods                  # pod sandbox trên node
crictl logs <container-id>   # log
crictl logs --tail 20 <id>
crictl inspect <id>          # chi tiết, có cả exit code
crictl images                # image trên node
crictl pull nginx:1.27
crictl rmi --prune           # xoá image không dùng
crictl exec -it <id> sh
```
Cấu hình endpoint (thường đã có sẵn):
```bash
cat /etc/crictl.yaml
# runtime-endpoint: unix:///run/containerd/containerd.sock
crictl --runtime-endpoint unix:///run/containerd/containerd.sock ps
```

## ctr – công cụ gốc của containerd
Ít dùng trong thi. Image của K8s nằm trong namespace `k8s.io` của containerd:
```bash
ctr -n k8s.io images ls
ctr -n k8s.io images import app.tar      # nạp image từ file tar
```

## Cấu hình containerd
File `/etc/containerd/config.toml`. Điểm quan trọng khi cài K8s là bật **systemd cgroup driver** cho khớp với kubelet:
```bash
containerd config default | sudo tee /etc/containerd/config.toml
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
sudo systemctl restart containerd
```
(Với containerd 2.x, cấu trúc file đổi một chút nhưng tuỳ chọn `SystemdCgroup` vẫn nằm trong phần runtime `runc`; hãy kiểm tra bằng `grep SystemdCgroup`.)

## cri-dockerd
Nếu đề yêu cầu chạy K8s với Docker Engine:
```bash
sudo dpkg -i cri-dockerd_*.deb
sudo systemctl enable --now cri-docker.service cri-docker.socket
# kubelet/kubeadm trỏ tới socket: unix:///var/run/cri-dockerd.sock
```

:::ex
Trên control plane, liệt kê mọi container của kube-apiserver kể cả đã chết, và xem 20 dòng log cuối của container mới nhất.
:::sol
```bash
sudo crictl ps -a --name kube-apiserver
sudo crictl logs --tail 20 $(sudo crictl ps -a --name kube-apiserver -q | head -1)
```
:::end

:::ex
Liệt kê image trên node, ghi những image của `registry.k8s.io` vào `/root/k8s-images.txt`.
:::sol
```bash
sudo crictl images | grep registry.k8s.io > /root/k8s-images.txt
```
:::end

:::ex
Kubelet báo lỗi "container runtime is down". Liệt kê các bước kiểm tra.
:::sol
```bash
systemctl status containerd
journalctl -u containerd --no-pager | tail -30
ls -l /run/containerd/containerd.sock
cat /etc/crictl.yaml ; sudo crictl info | head
sudo systemctl restart containerd && sudo systemctl restart kubelet
# Kiểm tra cờ --container-runtime-endpoint của kubelet (trong /var/lib/kubelet/kubeadm-flags.env
# hoặc containerRuntimeEndpoint trong /var/lib/kubelet/config.yaml)
```
:::end
