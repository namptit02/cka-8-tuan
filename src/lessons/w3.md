# L: ConfigMap và Secret

Tách cấu hình ra khỏi image để cùng một image chạy ở nhiều môi trường.

## Tạo
```bash
kubectl create cm app-cfg --from-literal=MODE=prod --from-literal=LOG=info
kubectl create cm nginx-conf --from-file=nginx.conf            # key = tên file
kubectl create cm envs --from-env-file=app.env                 # mỗi dòng KEY=VALUE
kubectl create secret generic db --from-literal=USER=admin --from-literal=PASS='p@ss'
kubectl create secret tls web-tls --cert=tls.crt --key=tls.key
kubectl create secret docker-registry regcred --docker-server=reg.io --docker-username=u --docker-password=p
```

## Dùng trong Pod – 3 cách
```yaml
spec:
  containers:
  - name: app
    image: busybox
    command: ["sleep","3600"]
    env:                                   # 1. từng biến
    - name: APP_MODE
      valueFrom:
        configMapKeyRef: {name: app-cfg, key: MODE}
    - name: DB_PASS
      valueFrom:
        secretKeyRef: {name: db, key: PASS}
    envFrom:                               # 2. toàn bộ key thành biến
    - configMapRef: {name: app-cfg}
    - secretRef: {name: db}
    volumeMounts:                          # 3. thành file
    - name: conf
      mountPath: /etc/nginx/conf.d
      readOnly: true
  volumes:
  - name: conf
    configMap: {name: nginx-conf}
  # secret: {secretName: db}
```
- Mount dạng volume: mỗi key thành một file. Cập nhật ConfigMap → file tự cập nhật sau ~1 phút (trừ khi dùng `subPath`).
- Biến môi trường **không** tự cập nhật, phải restart pod (`kubectl rollout restart`).
- Secret chỉ là base64. Muốn bảo mật thật: RBAC hạn chế đọc secret và bật encryption at rest cho etcd.
- `immutable: true` để khoá ConfigMap/Secret không cho sửa.

:::ex
Tạo ConfigMap `w3-cfg` có `COLOR=blue`, Secret `w3-sec` có `TOKEN=abc123`. Tạo pod `w3-app` (busybox, sleep 3600) có biến `COLOR` lấy từ ConfigMap và biến `API_TOKEN` lấy từ key `TOKEN` của Secret. Kiểm tra.
:::sol
```bash
kubectl create cm w3-cfg --from-literal=COLOR=blue
kubectl create secret generic w3-sec --from-literal=TOKEN=abc123
kubectl run w3-app --image=busybox --dry-run=client -o yaml --command -- sleep 3600 > w3.yaml
```
Thêm vào container:
```yaml
    env:
    - name: COLOR
      valueFrom: {configMapKeyRef: {name: w3-cfg, key: COLOR}}
    - name: API_TOKEN
      valueFrom: {secretKeyRef: {name: w3-sec, key: TOKEN}}
```
```bash
kubectl apply -f w3.yaml
kubectl exec w3-app -- env | grep -E 'COLOR|API_TOKEN'
```
:::end

:::ex
Mount Secret `w3-sec` vào pod nginx tại `/etc/secret`, chỉ đọc. Kiểm tra file `/etc/secret/TOKEN`.
:::sol
```yaml
spec:
  containers:
  - name: nginx
    image: nginx
    volumeMounts:
    - {name: s, mountPath: /etc/secret, readOnly: true}
  volumes:
  - name: s
    secret: {secretName: w3-sec}
```
```bash
kubectl exec <pod> -- cat /etc/secret/TOKEN     # abc123 (đã giải mã)
```
:::end

:::ex
Đọc giá trị gốc của key `PASS` trong Secret `db` và ghi vào `/root/pass.txt`.
:::sol
```bash
kubectl get secret db -o jsonpath='{.data.PASS}' | base64 -d > /root/pass.txt
```
:::end

# L: Tài nguyên: requests, limits, QoS, quota

## Requests và limits
```yaml
resources:
  requests: {cpu: 250m, memory: 128Mi}   # scheduler dùng để chọn node
  limits:   {cpu: 500m, memory: 256Mi}   # trần khi chạy
```
- CPU: `1` = 1 core, `250m` = 0,25 core. Vượt limit CPU → bị **bóp** (throttle), không chết.
- Memory: `Mi`, `Gi`. Vượt limit memory → **OOMKilled** (exit 137).
- Scheduler chỉ nhìn **requests**: node phải còn đủ (allocatable − tổng requests đã có). Thiếu → pod Pending "Insufficient cpu".
- `kubectl describe node` → mục "Allocated resources" xem đã dùng bao nhiêu.

## QoS class
| Class | Điều kiện | Bị đuổi khi node thiếu RAM |
|---|---|---|
| Guaranteed | mọi container có requests = limits cho cả cpu và memory | sau cùng |
| Burstable | có requests/limits nhưng không thuộc trên | giữa |
| BestEffort | không đặt gì | đầu tiên |

## LimitRange – mặc định cho từng pod/container trong namespace
```yaml
apiVersion: v1
kind: LimitRange
metadata: {name: defaults, namespace: dev}
spec:
  limits:
  - type: Container
    default: {cpu: 500m, memory: 256Mi}          # limits mặc định
    defaultRequest: {cpu: 100m, memory: 128Mi}   # requests mặc định
    max: {memory: 1Gi}
```

## ResourceQuota – tổng trần của namespace
```bash
kubectl create quota dev-quota -n dev --hard=pods=10,requests.cpu=2,requests.memory=4Gi,limits.memory=8Gi
kubectl describe quota -n dev
```
Khi có quota về cpu/memory, mọi pod mới **bắt buộc** khai báo requests/limits (hoặc có LimitRange mặc định), nếu không sẽ bị từ chối.

## PriorityClass
```bash
kubectl create priorityclass high --value=100000 --description="quan trọng"
kubectl get priorityclass     # có sẵn system-cluster-critical, system-node-critical
```
Pod có `priorityClassName: high` được ưu tiên schedule và có thể **đẩy (preempt)** pod ưu tiên thấp hơn khi node đầy.

:::ex
Tạo pod `qos-g` có QoS Guaranteed (nginx). Kiểm tra QoS class.
:::sol
```yaml
resources:
  requests: {cpu: 100m, memory: 64Mi}
  limits:   {cpu: 100m, memory: 64Mi}
```
```bash
kubectl get po qos-g -o jsonpath='{.status.qosClass}'    # Guaranteed
```
:::end

:::ex
Tạo pod `oom` image `polinux/stress` với limit memory 50Mi, chạy `stress --vm 1 --vm-bytes 100M`. Quan sát trạng thái và lý do.
:::sol
```yaml
spec:
  containers:
  - name: s
    image: polinux/stress
    command: ["stress"]
    args: ["--vm","1","--vm-bytes","100M","--vm-hang","1"]
    resources: {limits: {memory: 50Mi}}
```
```bash
kubectl get po oom -w          # OOMKilled -> CrashLoopBackOff
kubectl describe po oom | grep -A3 "Last State"   # Reason: OOMKilled, Exit Code: 137
```
:::end

:::ex
Namespace `w3q`: giới hạn tối đa 3 pod và tổng requests.cpu 1. Thêm LimitRange để container không khai báo vẫn có requests cpu 200m. Thử tạo 5 pod.
:::sol
```bash
kubectl create ns w3q
kubectl create quota q -n w3q --hard=pods=3,requests.cpu=1
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: LimitRange
metadata: {name: lr, namespace: w3q}
spec:
  limits:
  - type: Container
    defaultRequest: {cpu: 200m}
    default: {cpu: 400m}
EOF
for i in 1 2 3 4 5; do kubectl run p$i --image=nginx -n w3q; done
# p4, p5 bị từ chối: exceeded quota pods=3
kubectl describe quota q -n w3q
```
:::end

:::ex
Một pod Pending với event "0/2 nodes are available: 2 Insufficient memory". Có những cách sửa nào?
:::sol
Giảm `requests.memory` của pod; giảm số replica/xoá pod khác để giải phóng; thêm node hoặc node lớn hơn. Kiểm tra:
```bash
kubectl describe node | grep -A8 "Allocated resources"
```
:::end

# L: Probe và autoscaling (HPA)

## 3 loại probe
| Probe | Fail thì sao | Dùng khi |
|---|---|---|
| **livenessProbe** | kubelet **restart** container | app treo nhưng process chưa chết |
| **readinessProbe** | pod bị **bỏ khỏi endpoints** của Service (không nhận traffic), không restart | app chưa sẵn sàng / đang quá tải |
| **startupProbe** | tạm khoá 2 probe trên cho tới khi pass; fail quá số lần → restart | app khởi động chậm |

```yaml
livenessProbe:
  httpGet: {path: /healthz, port: 8080}
  initialDelaySeconds: 10
  periodSeconds: 5
  failureThreshold: 3
readinessProbe:
  tcpSocket: {port: 3306}
startupProbe:
  exec: {command: ["cat", "/tmp/ready"]}
  failureThreshold: 30
  periodSeconds: 10      # cho tối đa 300s để khởi động
```
Kiểu kiểm tra: `httpGet` (mã 200–399 là ok), `tcpSocket`, `exec` (exit 0 là ok), `grpc`.

## HorizontalPodAutoscaler
Tự tăng/giảm số replica theo CPU/memory. Cần **metrics-server** và pod phải khai báo **requests**.
```bash
kubectl top nodes           # nếu lỗi "Metrics API not available" → chưa có metrics-server
kubectl autoscale deploy web --min=2 --max=10 --cpu-percent=70
kubectl get hpa
```
YAML đầy đủ (dùng khi đề yêu cầu memory hoặc behavior):
```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata: {name: web}
spec:
  scaleTargetRef: {apiVersion: apps/v1, kind: Deployment, name: web}
  minReplicas: 2
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: memory
      target: {type: Utilization, averageUtilization: 80}
  behavior:
    scaleDown: {stabilizationWindowSeconds: 60}
```
- Công thức: `replicas mong muốn = ceil(replicas hiện tại × giá trị hiện tại / mục tiêu)`.
- **VPA** (Vertical Pod Autoscaler) điều chỉnh requests/limits thay vì số pod; là add-on, chỉ cần biết khái niệm.

:::ex
Tạo pod `live` (busybox) chạy `touch /tmp/ok; sleep 30; rm /tmp/ok; sleep 600` với livenessProbe `cat /tmp/ok` mỗi 5s. Quan sát RESTARTS tăng.
:::sol
```yaml
spec:
  containers:
  - name: c
    image: busybox
    command: ["sh","-c","touch /tmp/ok; sleep 30; rm /tmp/ok; sleep 600"]
    livenessProbe:
      exec: {command: ["cat","/tmp/ok"]}
      initialDelaySeconds: 5
      periodSeconds: 5
```
```bash
kubectl get po live -w      # sau ~45s RESTARTS = 1
kubectl describe po live | grep -i liveness
```
:::end

:::ex
Deployment `web` 3 replica có Service. Thêm readinessProbe kiểm tra file `/tmp/ready` (không tồn tại). Điều gì xảy ra với endpoints của Service?
:::sol
Mọi pod `READY 0/1`, không bị restart, Service không còn endpoint nào:
```bash
kubectl get po ; kubectl get endpointslices -l kubernetes.io/service-name=web
kubectl exec <pod> -- touch /tmp/ready     # pod đó Ready và có lại trong endpoints
```
:::end

:::ex
Cài metrics-server (lab có thể cần cờ `--kubelet-insecure-tls`), tạo HPA cho deployment `web`: CPU 50%, min 1, max 4. Deployment cần gì để HPA hoạt động?
:::sol
```bash
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
# lab tự dựng: kubectl edit deploy metrics-server -n kube-system, thêm arg --kubelet-insecure-tls
kubectl set resources deploy web --requests=cpu=100m
kubectl autoscale deploy web --cpu-percent=50 --min=1 --max=4
kubectl get hpa web      # TARGETS hiện cpu: x%/50%, không phải <unknown>
```
Deployment phải có `resources.requests.cpu`.
:::end

# L: Scheduling: nodeSelector, affinity, taint/toleration

## nodeName & nodeSelector
```yaml
spec:
  nodeName: node01          # bỏ qua scheduler, gán thẳng (ít dùng)
  nodeSelector:
    disktype: ssd           # node phải có label này
```
```bash
kubectl label node node01 disktype=ssd
kubectl get nodes --show-labels
```

## Node affinity – điều kiện linh hoạt hơn
```yaml
affinity:
  nodeAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:     # BẮT BUỘC
      nodeSelectorTerms:
      - matchExpressions:
        - {key: disktype, operator: In, values: [ssd, nvme]}
    preferredDuringSchedulingIgnoredDuringExecution:    # ƯU TIÊN
    - weight: 50
      preference:
        matchExpressions:
        - {key: zone, operator: In, values: [a]}
```
Toán tử: `In`, `NotIn`, `Exists`, `DoesNotExist`, `Gt`, `Lt`.

## Pod affinity / anti-affinity – theo vị trí pod khác
```yaml
affinity:
  podAntiAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
    - labelSelector:
        matchLabels: {app: web}
      topologyKey: kubernetes.io/hostname     # không đặt 2 pod app=web trên cùng 1 node
```

## Taint và toleration – node "đuổi" pod
- **Taint** đặt trên node: "đừng đặt pod ở đây trừ khi chịu được".
- **Toleration** đặt trên pod: "tôi chịu được taint này". Toleration **không bắt** pod phải lên node đó; muốn ép thì kết hợp nodeSelector/affinity.
```bash
kubectl taint node node01 dedicated=gpu:NoSchedule
kubectl taint node node01 dedicated=gpu:NoSchedule-     # gỡ
kubectl describe node controlplane | grep Taints        # node-role.kubernetes.io/control-plane:NoSchedule
```
```yaml
tolerations:
- key: dedicated
  operator: Equal        # hoặc Exists (không cần value)
  value: gpu
  effect: NoSchedule
```
| Effect | Ý nghĩa |
|---|---|
| NoSchedule | pod mới không chịu được thì không vào |
| PreferNoSchedule | cố tránh |
| NoExecute | đuổi luôn cả pod đang chạy không chịu được |

## Cordon, drain
```bash
kubectl cordon node01            # không nhận pod mới (SchedulingDisabled)
kubectl drain node01 --ignore-daemonsets --delete-emptydir-data   # đuổi pod đi để bảo trì
kubectl uncordon node01
```

:::ex
Gắn label `w3=fast` cho node01. Tạo deployment `fast` 2 replica chỉ được chạy trên node có label đó, dùng node affinity bắt buộc.
:::sol
```bash
kubectl label node node01 w3=fast
kubectl create deploy fast --image=nginx --replicas=2 --dry-run=client -o yaml > fast.yaml
```
Thêm vào `spec.template.spec`:
```yaml
      affinity:
        nodeAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            nodeSelectorTerms:
            - matchExpressions:
              - {key: w3, operator: In, values: [fast]}
```
```bash
kubectl apply -f fast.yaml && kubectl get po -o wide -l app=fast
```
:::end

:::ex
Chạy một pod trên control plane node (bình thường bị taint chặn) mà không gỡ taint.
:::sol
```yaml
spec:
  nodeName: controlplane     # hoặc nodeSelector: {node-role.kubernetes.io/control-plane: ""}
  tolerations:
  - key: node-role.kubernetes.io/control-plane
    operator: Exists
    effect: NoSchedule
  containers:
  - {name: c, image: nginx}
```
:::end

:::ex
Deployment `spread` 3 replica sao cho không có 2 pod nào trên cùng một node. Trong cluster 2 worker, chuyện gì xảy ra với pod thứ 3?
:::sol
Dùng `podAntiAffinity` required với `topologyKey: kubernetes.io/hostname` và `labelSelector app=spread`. Với 2 worker (control plane bị taint), pod thứ 3 **Pending** vì không node nào thoả điều kiện.
:::end

:::ex
Bảo trì node01: chuyển hết pod đi nơi khác, sau đó cho nó nhận pod lại.
:::sol
```bash
kubectl drain node01 --ignore-daemonsets --delete-emptydir-data
kubectl get nodes      # node01 Ready,SchedulingDisabled
kubectl uncordon node01
```
Pod do Deployment quản lý được tạo lại ở node khác; pod "trần" không có controller sẽ bị xoá mất (drain cần `--force`).
:::end

# L: DaemonSet, Job, CronJob, init và sidecar container

## DaemonSet – mỗi node một pod
Dùng cho agent: kube-proxy, CNI, thu thập log, giám sát.
```bash
kubectl create deploy agent --image=fluent/fluent-bit --dry-run=client -o yaml > ds.yaml
# sửa: kind: DaemonSet, xoá replicas, strategy, status
kubectl get ds -A
```

## StatefulSet (khái niệm)
Pod có tên cố định (`db-0`, `db-1`), khởi động theo thứ tự, mỗi pod có PVC riêng (`volumeClaimTemplates`), cần **headless Service**. Dùng cho database.

## Job và CronJob
```bash
kubectl create job pi --image=perl:5.34 -- perl -Mbignum=bpi -wle 'print bpi(200)'
kubectl create cronjob backup --image=busybox --schedule="0 2 * * *" -- sh -c "date"
kubectl create job manual-run --from=cronjob/backup     # chạy cronjob ngay
```
Trường quan trọng của Job: `completions`, `parallelism`, `backoffLimit`, `activeDeadlineSeconds`, `ttlSecondsAfterFinished`. Pod của Job phải có `restartPolicy: Never` hoặc `OnFailure`.
CronJob: `schedule` (cú pháp cron: phút giờ ngày tháng thứ), `successfulJobsHistoryLimit`, `failedJobsHistoryLimit`, `concurrencyPolicy` (Allow/Forbid/Replace).

## Init container
Chạy **trước** container chính, lần lượt, phải xong (exit 0) thì container chính mới chạy. Dùng để đợi phụ thuộc, chuẩn bị file.
```yaml
initContainers:
- name: wait-db
  image: busybox
  command: ["sh","-c","until nslookup db; do sleep 2; done"]
```

## Sidecar container (native, stable từ 1.33)
Init container có `restartPolicy: Always` → khởi động trước, **chạy suốt** cùng container chính, tự dừng sau container chính. Dùng cho log shipper, proxy.
```yaml
initContainers:
- name: log-shipper
  image: busybox
  restartPolicy: Always
  command: ["sh","-c","tail -F /var/log/app/app.log"]
  volumeMounts: [{name: logs, mountPath: /var/log/app}]
containers:
- name: app
  image: busybox
  command: ["sh","-c","while true; do date >> /var/log/app/app.log; sleep 2; done"]
  volumeMounts: [{name: logs, mountPath: /var/log/app}]
volumes:
- name: logs
  emptyDir: {}
```

:::ex
Tạo DaemonSet `node-agent` (busybox, `sleep infinity`) chạy trên **mọi** node kể cả control plane.
:::sol
```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata: {name: node-agent}
spec:
  selector: {matchLabels: {app: node-agent}}
  template:
    metadata: {labels: {app: node-agent}}
    spec:
      tolerations:
      - {key: node-role.kubernetes.io/control-plane, operator: Exists, effect: NoSchedule}
      containers:
      - {name: a, image: busybox, command: ["sleep","infinity"]}
```
```bash
kubectl get ds node-agent ; kubectl get po -l app=node-agent -o wide
```
:::end

:::ex
Tạo Job `count` chạy 6 lần hoàn thành, mỗi lúc chạy song song 2, mỗi pod in `echo done`, thử lại tối đa 2 lần, tự xoá sau 120s khi xong.
:::sol
```bash
kubectl create job count --image=busybox --dry-run=client -o yaml -- echo done > job.yaml
```

```yaml

```
:::end
