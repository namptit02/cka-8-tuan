# L: kubeadm init, join và kiến trúc HA

## kubeadm init làm gì
1. **preflight**: kiểm tra swap, port, runtime, quyền root.
2. **certs**: tạo CA và chứng chỉ trong `/etc/kubernetes/pki/`.
3. **kubeconfig**: tạo `admin.conf`, `kubelet.conf`, `controller-manager.conf`, `scheduler.conf` (và `super-admin.conf`).
4. **control-plane + etcd**: ghi static pod manifests vào `/etc/kubernetes/manifests/`.
5. **kubelet-start**, đợi control plane khoẻ.
6. **upload-config**, **mark-control-plane** (thêm taint), **bootstrap-token**, **addons** (CoreDNS, kube-proxy).

```bash
sudo kubeadm init \
  --pod-network-cidr=10.244.0.0/16 \
  --apiserver-advertise-address=192.168.56.10 \
  --kubernetes-version=v1.35.0 \
  --control-plane-endpoint=k8s-api.local:6443     # cần khi muốn HA về sau
# hoặc dùng file: kubeadm init --config kubeadm.yaml
kubeadm config print init-defaults           # xem cấu hình mặc định
```

## join
```bash
kubeadm token list
kubeadm token create --print-join-command    # token mặc định hết hạn sau 24h
# worker
sudo kubeadm join 192.168.56.10:6443 --token abc.def --discovery-token-ca-cert-hash sha256:...
# thêm control plane (HA)
sudo kubeadm init phase upload-certs --upload-certs     # in ra certificate key
sudo kubeadm join ... --control-plane --certificate-key <key>
```

## Gỡ node
```bash
kubectl drain node02 --ignore-daemonsets --delete-emptydir-data
kubectl delete node node02
# trên node02:
sudo kubeadm reset -f
```

## HA control plane (khái niệm)
- ≥ 3 control plane node phía sau **load balancer** cho port 6443.
- **Stacked etcd**: etcd chạy trên chính các control plane node (mặc định của kubeadm). Đơn giản, nhưng mất node là mất cả apiserver lẫn etcd member.
- **External etcd**: cụm etcd riêng. Phức tạp hơn, tách rủi ro.
- etcd cần **đa số (quorum)**: 3 member chịu được mất 1, 5 member chịu được mất 2. Vì vậy số member luôn lẻ.

:::ex
Trên cluster đang chạy, worker mới cần join nhưng token cũ đã hết hạn. Tạo lệnh join mới và ghi vào `/root/join.sh`.
:::sol
```bash
kubeadm token create --print-join-command > /root/join.sh
cat /root/join.sh
```
:::end

:::ex
Gỡ node01 khỏi cluster một cách sạch sẽ, sau đó join lại.
:::sol
```bash
kubectl drain node01 --ignore-daemonsets --delete-emptydir-data
kubectl delete node node01
ssh node01 'sudo kubeadm reset -f'
kubeadm token create --print-join-command      # chạy kết quả trên node01 với sudo
kubectl get nodes
```
:::end

:::ex
Liệt kê các file kubeconfig mà kubeadm sinh ra và cho biết mỗi file do thành phần nào dùng.
:::sol
```bash
ls /etc/kubernetes/*.conf
```
- `admin.conf`: quản trị viên (kubectl).
- `super-admin.conf`: quyền vượt RBAC, chỉ dùng khẩn cấp.
- `kubelet.conf`: kubelet của node đó.
- `controller-manager.conf`, `scheduler.conf`: 2 thành phần control plane tương ứng.
:::end

# L: Nâng cấp cluster bằng kubeadm

## Quy tắc
- Chỉ nâng **1 minor** mỗi lần (1.34 → 1.35, không nhảy 1.33 → 1.35).
- Thứ tự: **control plane trước**, rồi từng worker.
- kubelet có thể cũ hơn apiserver tối đa 3 minor, không được mới hơn.
- Luôn **backup etcd** trước khi nâng (thực tế; đề thường không hỏi).

## Control plane
```bash
# 0. Nếu lên minor mới: đổi repo
sudo sed -i 's/v1.34/v1.35/' /etc/apt/sources.list.d/kubernetes.list
sudo apt-get update
apt-cache madison kubeadm                 # chọn version, ví dụ 1.35.2-1.1

# 1. Nâng kubeadm
sudo apt-mark unhold kubeadm
sudo apt-get install -y kubeadm='1.35.2-*'
sudo apt-mark hold kubeadm
kubeadm version

# 2. Xem kế hoạch và áp dụng
sudo kubeadm upgrade plan
sudo kubeadm upgrade apply v1.35.2        # control plane đầu tiên
# (control plane thứ 2, 3: sudo kubeadm upgrade node)

# 3. Nâng kubelet, kubectl
kubectl drain controlplane --ignore-daemonsets
sudo apt-mark unhold kubelet kubectl
sudo apt-get install -y kubelet='1.35.2-*' kubectl='1.35.2-*'
sudo apt-mark hold kubelet kubectl
sudo systemctl daemon-reload && sudo systemctl restart kubelet
kubectl uncordon controlplane
```

## Worker (lặp cho từng node)
```bash
ssh node01
# đổi repo nếu lên minor mới, apt-get update
sudo apt-mark unhold kubeadm && sudo apt-get install -y kubeadm='1.35.2-*' && sudo apt-mark hold kubeadm
sudo kubeadm upgrade node
exit
kubectl drain node01 --ignore-daemonsets --delete-emptydir-data    # chạy từ control plane
ssh node01
sudo apt-mark unhold kubelet kubectl && sudo apt-get install -y kubelet='1.35.2-*' kubectl='1.35.2-*' && sudo apt-mark hold kubelet kubectl
sudo systemctl daemon-reload && sudo systemctl restart kubelet
exit
kubectl uncordon node01
kubectl get nodes          # cột VERSION
```

:::ex
Trên lab tự dựng ở bản minor cũ (ví dụ 1.34), nâng toàn bộ cluster lên minor tiếp theo. Tiêu chí: `kubectl get nodes` cả 2 node hiển thị version mới và Ready, mọi pod kube-system Running.
:::sol
Làm theo đúng các bước ở trên. Kiểm tra:
```bash
kubectl get nodes
kubectl version
kubectl get po -n kube-system
```
Lỗi hay gặp: quên `apt-mark unhold`, quên đổi repo minor, quên `daemon-reload`, quên `uncordon`.
:::end

:::ex
Đề chỉ yêu cầu: "Nâng control plane node lên 1.35.2, **không** nâng worker". Viết các lệnh tối thiểu.
:::sol
```bash
sudo apt-mark unhold kubeadm kubelet kubectl
sudo apt-get update && sudo apt-get install -y kubeadm='1.35.2-*'
sudo kubeadm upgrade apply v1.35.2 -y
kubectl drain controlplane --ignore-daemonsets
sudo apt-get install -y kubelet='1.35.2-*' kubectl='1.35.2-*'
sudo apt-mark hold kubeadm kubelet kubectl
sudo systemctl daemon-reload && sudo systemctl restart kubelet
kubectl uncordon controlplane
```
:::end

# L: Sao lưu và khôi phục etcd

## Lấy thông tin kết nối
```bash
cat /etc/kubernetes/manifests/etcd.yaml | grep -E 'listen-client|cert-file|key-file|trusted-ca|data-dir'
# --listen-client-urls=https://127.0.0.1:2379,...
# --cert-file=/etc/kubernetes/pki/etcd/server.crt
# --key-file=/etc/kubernetes/pki/etcd/server.key
# --trusted-ca-file=/etc/kubernetes/pki/etcd/ca.crt
# --data-dir=/var/lib/etcd
```

## Backup
```bash
ETCDCTL_API=3 etcdctl \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  snapshot save /opt/backup/etcd.db

etcdutl snapshot status /opt/backup/etcd.db -w table      # kiểm tra
```
(etcdctl từ bản 3.4 mặc định dùng API v3; ghi `ETCDCTL_API=3` cũng không sao.)

## Restore
```bash
# 1. Khôi phục ra thư mục dữ liệu MỚI
sudo etcdutl snapshot restore /opt/backup/etcd.db --data-dir /var/lib/etcd-from-backup
#    (bản cũ: ETCDCTL_API=3 etcdctl snapshot restore ... --data-dir ...)

# 2. Trỏ etcd sang thư mục mới
sudo vim /etc/kubernetes/manifests/etcd.yaml
#   volumes:
#   - hostPath:
#       path: /var/lib/etcd-from-backup     # ← đổi chỗ này
#       type: DirectoryOrCreate
#     name: etcd-data

# 3. Đợi etcd và apiserver khởi động lại (1–2 phút)
watch sudo crictl ps          # etcd, kube-apiserver chạy lại
kubectl get po -A
```
- Chỉ cần đổi `hostPath.path`. Nếu đổi cả `--data-dir` thì phải đổi `mountPath` cho khớp.
- Nếu cluster có etcd ngoài (external), restore trên máy etcd và sửa service systemd của etcd thay vì static pod.
- Nếu apiserver kẹt, có thể tạm move file `kube-apiserver.yaml` ra khỏi thư mục manifests trong lúc restore rồi đưa lại.

:::ex
Tạo deployment `before-backup`. Backup etcd ra `/opt/etcd-w6.db`. Xoá deployment đó và tạo deployment `after-backup`. Restore từ snapshot. Kết quả mong đợi?
:::sol
```bash
kubectl create deploy before-backup --image=nginx
sudo ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key snapshot save /opt/etcd-w6.db
kubectl delete deploy before-backup ; kubectl create deploy after-backup --image=nginx
sudo etcdutl snapshot restore /opt/etcd-w6.db --data-dir /var/lib/etcd-w6
sudo sed -i 's#path: /var/lib/etcd$#path: /var/lib/etcd-w6#' /etc/kubernetes/manifests/etcd.yaml
# đợi 1-2 phút
kubectl get deploy        # có before-backup, KHÔNG có after-backup
```
:::end

:::ex
Liệt kê thành viên cụm etcd và kiểm tra sức khoẻ endpoint.
:::sol
```bash
export ETCDCTL_API=3
OPTS="--endpoints=https://127.0.0.1:2379 --cacert=/etc/kubernetes/pki/etcd/ca.crt --cert=/etc/kubernetes/pki/etcd/server.crt --key=/etc/kubernetes/pki/etcd/server.key"
sudo -E etcdctl $OPTS member list -w table
sudo -E etcdctl $OPTS endpoint health
```
:::end

# L: Runtime, chứng chỉ và cấu hình node

## Container runtime cho kubeadm
- kubeadm tự tìm socket CRI. Nếu máy có nhiều runtime, chỉ định: `--cri-socket unix:///var/run/cri-dockerd.sock`.
- Cgroup driver của kubelet (mặc định `systemd` khi cài bằng kubeadm) **phải khớp** với runtime (`SystemdCgroup = true` trong containerd).

## Cài cri-dockerd (dạng đề mới)
```bash
sudo dpkg -i /root/cri-dockerd_0.3.x.ubuntu-jammy_amd64.deb
sudo systemctl enable --now cri-docker.service
systemctl status cri-docker
# kèm sysctl:
cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables = 1
net.ipv6.conf.all.forwarding = 1
net.ipv4.ip_forward = 1
net.netfilter.nf_conntrack_max = 131072
EOF
sudo sysctl --system
```

## Chứng chỉ
```bash
sudo kubeadm certs check-expiration        # hạn từng cert (mặc định 1 năm, CA 10 năm)
sudo kubeadm certs renew all               # gia hạn tất cả
# sau đó restart static pod control plane: move manifests ra rồi vào lại, hoặc restart kubelet
openssl x509 -in /etc/kubernetes/pki/apiserver.crt -noout -text | grep -A2 -E "Validity|Subject Alternative"
```
`kubeadm upgrade apply` cũng tự gia hạn chứng chỉ.

## Cấu hình kubelet
```bash
cat /var/lib/kubelet/config.yaml       # clusterDNS, staticPodPath, cgroupDriver, evictionHard...
cat /var/lib/kubelet/kubeadm-flags.env
kubectl get cm kubelet-config -n kube-system -o yaml    # cấu hình chung cho cả cluster
```

:::ex
Kiểm tra ngày hết hạn chứng chỉ của apiserver bằng 2 cách và ghi ngày hết hạn vào `/root/apiserver-expiry.txt`.
:::sol
```bash
sudo kubeadm certs check-expiration | grep -w apiserver
sudo openssl x509 -in /etc/kubernetes/pki/apiserver.crt -noout -enddate > /root/apiserver-expiry.txt
```
:::end

:::ex
Liệt kê các tên (SAN) trong chứng chỉ của apiserver. Tên nào cho phép pod gọi `https://kubernetes.default.svc`?
:::sol
```bash
sudo openssl x509 -in /etc/kubernetes/pki/apiserver.crt -noout -text | grep -A1 "Subject Alternative Name"
```
Các SAN `kubernetes`, `kubernetes.default`, `kubernetes.default.svc`, `kubernetes.default.svc.cluster.local` và IP đầu tiên của Service CIDR (ví dụ `10.96.0.1`).
:::end

:::ex
Kiểm tra cgroup driver của kubelet và của containerd có khớp không.
:::sol
```bash
grep cgroupDriver /var/lib/kubelet/config.yaml           # systemd
grep SystemdCgroup /etc/containerd/config.toml           # true
```
:::end
